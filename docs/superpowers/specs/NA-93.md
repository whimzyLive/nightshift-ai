## Overview

A `sdlc:loop` pass is a deterministic status probe followed by a first-match-wins decision table, and today it executes on the session model against a 254,390-token resident context. H moves the probe-and-decide body into a synchronous `haiku`-routed subagent that returns a decision token; every side effect — budget accounting, `/review-fix`, the in-session review, `--on-clean`, session release — stays at the top level on the session model.

## Backend Implementation

### The routing rule (satisfies AC-1)

```text
routable := a unit of work that (a) reads only script output already on disk or stdout,
            (b) applies a fixed, first-match-wins table over integers,
            (c) produces a token from a closed enum, and
            (d) performs NO side effect of its own
routable -> dispatch to `general-purpose` at model=<resolved>, run_in_background:false;
            return the block below and nothing else
NOT routable -> stays on the session model, no exception:
   /review-fix and the in-session REVIEW_CMD      # they edit, push, and post
   loop-budget.sh init/check                      # session-scoped state; see the mechanism survey
   the review marker write                        # same temp scope as the budget file
   the --on-clean hook                            # the only irreversible action in the loop
   session-complete.sh                            # owns the single slot release
   the clean-predicate re-check                   # see The clean guard, below
```

Rationale as annotation: a routed unit that performs a side effect can be wrong in a way the caller cannot undo. Confining the subagent to classification makes every failure mode a mis-*label*, and every mis-label recoverable at the top level or bounded by the existing budget.

Return contract (verbatim; **cap 1,200 B**; one `KEY=value` per line, unknown keys ignored):

```text
DECISION=wait | fix | review | clean | halt
RULE=1 | 2a | 2b | 3 | 4 | 5 | 6 | 7 | CI-a | CI-b | CI-c | CI-c2 | CI-d | CI-e | CI-f

HEAD=<head oid | ->

RE_REQUEST=yes | no

```

`FIELDS` is the probe's own output re-emitted verbatim — never paraphrased, never re-derived. It is what the top level re-checks against.

### H2 — the top-level action table (`plugins/sdlc/commands/loop.md`, ai-enablement-engineer)

`commands/loop.md` keeps: argument parsing, Step 0 (review-config read), Step 1 (PR resolve), the budget call sites, the dispatch stub above, **the clean guard**, and this table:

```text
DECISION=wait   -> ASSERT clean-guard NOT satisfied
                   loop-budget.sh check "$HEAD" "$UNRESOLVED" [--grace iff GRACE=yes]
                   RE_REQUEST=yes AND REVIEW_MODE=on-update -> gh pr edit <PR> --add-reviewer @copilot
                   exit 0 -> schedule next iteration; exit 1 -> stop, print BUDGET_REASON + BLOCKED_BY
DECISION=fix    -> /review-fix <PR> INLINE (session model); on error or `Status: blocked` -> HALT
                   on-create -> stop after this single fix; on-update -> schedule next iteration
DECISION=review -> REVIEW_CMD INLINE (session model); write REVIEW_MARK; loop-budget.sh check; schedule
DECISION=clean  -> ASSERT clean-guard (below) ELSE treat as DECISION=halt
                   run --on-clean exactly once (if provided), then STOP (success)
DECISION=halt   -> print RULE, FIELDS, BLOCKED_BY; do NOT schedule a next iteration
unparseable / DECISION absent / RULE not in enum -> re-dispatch ONCE; second failure -> HALT
```

### H3 — the clean guard (the safety design, `commands/loop.md`, ai-enablement-engineer)

`DECISION=clean` is the **only** decision with an irreversible consequence: it runs `--on-clean`, which under `/auto` is the auto-merge. The orchestrator therefore never takes it on trust. It re-evaluates the predicate itself, from the individual integers in `FIELDS`:

```text
clean-guard(copilot)    := reviewed-head==1 AND changes-requested==0 AND unresolved==0
                           AND checks-failing==0 AND checks-pending==0
clean-guard(in-session) := reviewed-head==1 AND review-clean==1 AND unresolved==0
                           AND checks-failing==0 AND checks-pending==0
guard fails, or any named field is absent/non-numeric -> DECISION=halt, print "clean guard rejected
   a clean decision on <head> — <FIELDS>" and STOP.   # never fall through to --on-clean
```

Cost: five integer comparisons on values already in the return. Effect: the severe blast-radius class (merging an unreviewed, unresolved, or red-CI PR) requires the *probe script's own output* to be wrong, not the routed model. Rule 4 was already fully self-contained in the fast path (D7); H keeps only its predicate there and moves its prose.

The guard is **not** a substring match on the returned blob — it parses the named fields and compares each. A `grep -q clean` over the return would pass on the sentence "not clean"; this epic has already shipped four dead assertions of exactly that shape.

### H4 — the revert lever (satisfies AC-4)

**`SDLC_LOOP_MODEL`** — read by the dispatch stub, default `haiku` when unset.

```text
SDLC_LOOP_MODEL unset | haiku      -> model: "haiku"                      # H active
```

## Error Handling

| Scenario | Behaviour |
| --- | --- |
| Return block malformed, or `DECISION`/`RULE` outside its enum | Re-dispatch **once** with the contract restated; a second malformed return → **HALT** with the raw return printed. Never infer a decision from prose. |
| `DECISION=clean` but the clean guard rejects it | Treat as `halt`. `--on-clean` does not run. Print the guard's own message and `FIELDS`. This is the single most important row in this table. |
| `FIELDS` absent, or a named field non-numeric | Guard cannot evaluate → `halt`. Never default a missing field to a clean-compatible value. |
| Return exceeds the 1,200 B cap | Not a run failure — truncate and proceed if the named fields parsed; record `returnCapExceeded: true`, which **fails the pilot** (a round-trip is the failure mode routing exists to avoid). |
| Subagent runs `loop-budget.sh`, `tmp-dir.sh`, `/review-fix`, `session-complete.sh`, or any push/merge | Contract violation. Detected by the guard test asserting the prohibition text is present in the dispatch prompt, and at runtime by an unexpected `BUDGET_PASS_COUNT` jump. Treat a detected occurrence as **revert-now** (`SDLC_LOOP_MODEL=inherit`) and re-spec. |
| Dispatch fails, times out, or the harness rejects `model: "haiku"` | Fall back **once** to the same dispatch with the `model` key omitted (inherit). If that also fails → **HALT** the pass. Never fall back to evaluating the table inline: the table no longer lives at the top level, and improvising it is exactly the drift the gate exists to prevent. |
| `run_in_background` omitted or true | The pass returns with no decision. The malformed-return path catches it (no `DECISION=` line) and re-dispatches once, then HALTs. The guard test asserts `run_in_background: false` is present literally. |
| Haiku's 200K context window exceeded | Cannot occur by construction: the dispatch prompt is < 1 KB plus one ref (< 13 KB) plus one script's stdout. Asserted as a cap, not assumed. |
| `SDLC_LOOP_MODEL` set to an unrecognised value | WARNING on stderr, fall back to `haiku`. Never abort the loop on a config typo. |
| Cache-read ratio falls below 94% on the pilot | **Revert to `SDLC_LOOP_MODEL=inherit`. Never trade the guardrail for instruction surface** (AC-3, verbatim from the epic). |

## Blast radius of a wrong decision

Every cell states the cost and whether it is recoverable. `AS` = actual state; `RET` = what the routed subagent returned.

| AS → RET | What happens | Cost | Recoverable? |
| --- | --- | --- | --- |
| clean → wait | Loop spins; the idle budget (1200 s) or the 30-pass backstop stops it | ≤ 30 wasted passes; PR left open | **Yes** — bounded by `loop-budget.sh`, human merges |
| clean → fix | `/review-fix` runs with nothing to fix; HEAD usually does not move; next pass re-enters; budget bounds it | one wasted session-model fix round | **Yes** |
| clean → halt | Loop stops on a converged PR | one manual merge | **Yes** |
| fix → wait | Unresolved comments sit unaddressed until the budget trips | ≤ 20 min latency | **Yes** |
| fix → halt | Loop stops with actionable review feedback outstanding | manual `/review-fix` | **Yes** |
| wait → fix | `/review-fix` runs against a HEAD Copilot has not reviewed; may push a no-op commit | one wasted round + a HEAD move that resets the review | **Yes** |
| wait/fix/halt → **clean** (unreviewed HEAD) | `--on-clean` would merge an **unreviewed** PR | severe | **Blocked by the clean guard** (`reviewed-head==1`) |
| fix → **clean** (unresolved comments) | `--on-clean` would merge over open review threads | severe | **Blocked by the clean guard** (`unresolved==0 AND changes-requested==0`) |
| halt(rule 6) → **clean** (red CI) | `--on-clean` would merge with required checks failing | severe | **Blocked by the clean guard** (`checks-failing==0`), and by branch protection as a second backstop |
| any → halt on a state that should wait | Loop stops early | manual restart | **Yes** |
| Probe script itself returns wrong integers | Guard and subagent both consume the same wrong input | severe | **Not** addressed by H — `pr-loop-status.sh` is unchanged and out of scope |

**Summary.** Every recoverable class is bounded by the existing budget and costs at most one wasted round or ≤ 20 minutes of latency. Every severe class routes through `DECISION=clean`, and every severe class is refused by the clean guard unless the probe script's own integers are wrong — which H does not change and cannot make worse.

## Open Questions

- [ ] **The requests-per-story guardrail.** H adds ≈ 1 dispatch per loop pass, so the epic's literal "Requests per story must not increase" fails by construction — as it does for G. Does H get an explicit carve-out? — **Suggested default: yes.** Carve out request *count*, keep every token and resident guardrail, and record subagent dispatches as a separate, ungated row. Rationale: the epic's cost model is token-priced, and a guardrail that forbids trading expensive requests for cheap ones contradicts workstreams the epic itself sequences.
- [ ] **Opt-in gate vs model dial.** NA-91 shipped `SDLC_BOUNDARY_ON` default-unset. H proposes `SDLC_LOOP_MODEL` (default `haiku`) instead, because an opt-in gate would force `loop.md` to keep both the inline table and the stub, pushing the byte delta positive. — **Suggested default: the model dial as specced.** If the operator prefers strict opt-in, H's byte claim must be withdrawn and the spec re-scoped to routing only, with no relocation.
- [ ] **Does a subagent inherit `CLAUDE_CODE_SESSION_ID`?** Unverified — I could not dispatch an agent from this role to test it. H is designed to be correct either way (`DIR` passed literally; the subagent is forbidden from touching budget/temp scripts). — **Suggested default: keep the design as-is and add a one-line Phase-0 probe to the plan** (dispatch a `general-purpose` agent that runs `bash plugins/sdlc/scripts/session-key.sh` and compare its output to the parent's). If the key is inherited, the prohibition becomes belt-and-braces rather than load-bearing; if it is not, the prohibition is the only thing preventing a silently-reset loop budget.
- [ ] **Why route a deterministic table to a model at all, rather than to a script?** A `loop-decide.sh` would cost ~0 context and be exactly equivalent by construction. The story's AC-1 says "routed to a cheap (Haiku-class) subagent", and `loop-decide.py` is being built anyway as the oracle. — **Suggested default: ship H as specced (subagent), and record the script variant in the ADR as the named successor.** Deviating from AC-1's literal wording on the first workstream that can prove its own correctness would waste the proof; and the in-session path's CI-b/CI-c need judgment about `/code-review`'s reported finding count, which a script cannot supply.
- [ ] **Should H-Gate-4 be wired into CI?** It needs model calls and a Haiku dispatch, which CI does not have. — **Suggested default: author-run**, matching `artifact-contract.sh`, `context-residency.py`, and `work-placement.py`; H-Gate-1/2/3 are CI-wired and need no model.
- [ ] **Should the clean guard also cover `DECISION=fix`?** A spurious `fix` pushes a commit, which moves HEAD and resets the review. It is recoverable, but not free. — **Suggested default: no guard on `fix`.** `/review-fix` is itself a no-op when there is nothing to fix, and the budget bounds the loop. Guarding it would re-inline the rule-3 predicate and spend byte budget on a recoverable class.
