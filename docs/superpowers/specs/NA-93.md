## Deliberate deviation from AC-1 — read this first

AC-1 says the probe-and-decision body is "routed to a cheap (Haiku-class) subagent". **H ships a deterministic script instead.** Founder ruling, 2026-08-01.

```text
the decision table is a pure function of a bounded integer tuple   # 1,458 enumerable cases, proven below
a script is exactly equivalent, costs ~0 context, and cannot mis-decide
routing to a model buys nothing and adds a failure mode -> merging an unreviewed PR, or halting a healthy one
therefore: cheap := a script, not a cheap model
```

Precedent: NA-92's G3 shipped `scripts/docs-sync-gate.sh` over a subagent dispatch for the same reason, recorded in ADR 0019. H follows that pattern and its conventions. The deviation is carried into ADR 0020.

The subagent-routing mechanism was nonetheless verified before it was set aside; both findings are recorded in the Mechanism survey because a successor story that needs genuine judgement will otherwise re-derive them, and one of them is a silent hang.

## Overview

A `sdlc:loop` pass is a deterministic status probe followed by a first-match-wins decision table, and today it executes on the session model against a 254,390-token resident context. H moves the probe-and-decide body into `plugins/sdlc/scripts/loop-decide.sh`, which returns a decision token on stdout; every side effect — budget accounting, `/review-fix`, the in-session review, `--on-clean`, session release — stays at the top level on the session model.

## The decision domain — why AC-2 is provable, not sampled

The decision table is a pure function of a small, bounded integer tuple.

**Real observations.** 186 `loop-status:` lines across 38 corpus files, carrying only **9 distinct 8-tuples**:

| `(rh, cr, cp, un, pend, fail, pass, ra)` | Rule selected |
| --- | --- |
| `(0,0,0,0,0,0,0,0)` | 2a |
| `(0,0,0,0,0,0,0,1)` | 2b |
| `(0,0,0,1,0,0,0,1)` | 2b |
| `(0,0,0,2,0,0,0,1)` | 2b |
| `(1,0,0,0,0,0,0,1)` | 4 |
| `(1,0,0,1,0,0,0,1)` | 3 |
| `(1,0,0,2,0,0,0,1)` | 3 |
| `(1,0,0,3,0,0,0,1)` | 3 |
| `(1,0,0,4,0,0,0,1)` | 3 |

Observation counts by rule: **2a 126, 2b 38, 3 8, 4 14.**

> **Rules 1, 5, 6 and 7 have ZERO observations across the entire corpus.** Enumeration covers them; production never has. The golden for those four rows therefore encodes **intent — what the table says — not observed behaviour.** A green H-Gate-2 proves the bash port matches the markdown for rules 1/5/6/7; it proves nothing about whether those rows are *right*, because no real PR has exercised them. Do not let enumeration coverage be reported as production coverage. Rule 6 (failing checks → halt) and rule 7 (catch-all → halt) are the two that would matter most if wrong, and both are unexercised.

**Full domain enumeration.** Only the 0 / 1 / >1 distinction is load-bearing for the count fields, so the domain is finite and small:

```text
copilot domain := rh∈{0,1} × cr∈{0,1} × cp∈{0,1} × ra∈{0,1} × un∈{0,1,2} × pend∈{0,1,2}
                  × fail∈{0,1,2} × pass∈{0,1,2}                     = 2^4 · 3^4 = 1,296
in-session domain := reviewed-head∈{0,1} × review-clean∈{0,1,'-'} × unresolved∈{0,1,2}
                  × checks-pending∈{0,1,2} × checks-failing∈{0,1,2} = 2 · 3^4 = 162
total := 1,458 cases   # exhaustive, deterministic, zero model calls, CI-runnable
```

Because the decider is now a script, this enumeration is not a proxy for the shipped behaviour — it **is** the shipped behaviour, executed. H-Gate-2 runs the real `loop-decide.sh` over all 1,458 cases.

## Backend Implementation

### The offload rule (satisfies AC-1, as deviated)

```text
scriptable := a unit of work that (a) reads only script output or files already on disk,
              (b) applies a fixed, first-match-wins table over integers,
              (c) produces a token from a closed enum, and
              (d) performs NO side effect of its own
scriptable -> a contract-line script; emit the block below and nothing else; exit 0 always
NOT scriptable -> stays at the top level on the session model, no exception:
   /review-fix and the in-session REVIEW_CMD      # they edit, push, and post
   loop-budget.sh init/check                      # D8 — the budget script already owns the budget
   the review marker write                        # the top level owns what it will read back
   the --on-clean hook                            # the only irreversible action in the loop
   session-complete.sh                            # owns the single slot release
   the clean-predicate re-check                   # see H3
```

Rationale as annotation: `loop-decide.sh` owning the table and `loop-budget.sh` owning the budget preserves the D8 separation the A5 split established — one script per concern, and the command file still decides what to *do* with either answer.

### H1 — the decision script (`plugins/sdlc/scripts/loop-decide.sh`, ai-enablement-engineer)

Follows `docs-sync-gate.sh` conventions exactly: `set -uo pipefail`, an `emit()` helper, contract lines on stdout, a byte cap, `exit 0` always, and a fail-safe rule stated in the file header.

```text
usage: loop-decide.sh <PR> <copilot|in-session> <DIR> [REVIEW_MARK]
       loop-decide.sh --from-status "<loop-status line>"        # table only, no probe (test surface)
       loop-decide.sh --from-fields "<in-session field line>"   # table only, no probe (test surface)

stdout — exactly nine lines, first-match-wins, cap 600 B:
  DECISION=wait | fix | review | clean | halt
  RULE=1 | 2a | 2b | 3 | 4 | 5 | 6 | 7 | CI-a | CI-b | CI-c | CI-c2 | CI-d | CI-e | CI-f | unresolvable
  PATH=copilot | in-session
  HEAD=<head oid | ->
  UNRESOLVED=<N | ->
  FIELDS=<the probe's own integers, verbatim k=v, space-separated — never re-derived>
  GRACE=yes | no
  RE_REQUEST=yes | no
  BLOCKED_BY=<one line | none>

exit 0 ALWAYS. The script never halts the loop; commands/loop.md owns the consequence.
```

**Fail-safe direction, stated for H:** an unresolvable probe must never produce a decision that **merges** or **halts**.

```text
probe resolved, no rule matched        -> RULE=7,            DECISION=halt   # UNCHANGED — the table's own
                                                                             # catch-all, not a fail-safe path
loop-status line absent/unparseable    -> RULE=unresolvable,  DECISION=wait
a named field missing or non-numeric   -> RULE=unresolvable,  DECISION=wait
pr-loop-status.sh non-zero (it exits 0 today, but never assume) -> RULE=unresolvable, DECISION=wait
BLOCKED_BY carries the reason verbatim in every unresolvable case
```

`wait` is the only decision with no irreversible effect **and** a bound: `loop-budget.sh` stops a wait-looping pass at 1200 s idle or 30 passes, so an unresolvable probe degrades to a bounded stall with a printed reason — never to a merge, never to a premature halt. Note the existing behaviour this preserves: `pr-loop-status.sh` is best-effort and prints zeros on failure, and an all-zeros tuple already selects rule 2a (wait). H does **not** attempt to disambiguate a genuine unstarted review from a zeroed probe — that would be a behaviour change, and H changes no row.

Sections ported into the script:

| Ported from | Section | Bytes at HEAD |
| --- | --- | --- |
| `commands/loop.md` | Step 3 — probe (script call, 8-field description, status persist, progress capture) | 1,497 |
| `commands/loop.md` | Step 4 — decision table, rules 1–7 | 4,603 |
| `refs/loop-modes.md` | CI-1 — probe state + progress print | 2,057 |
| `refs/loop-modes.md` | CI-2 — decision table, rules CI-a…CI-f | 4,289 |
| **total ported** | | **12,446** |

**One `decide()` function, two entry points.** The probe path and the `--from-status` / `--from-fields` path MUST converge on a single `decide()` that takes the field tuple and returns the rule. A bifurcated implementation would let H-Gate-2 exhaustively test dead code while production runs a different table — the exact silent-pass shape this epic has caught four times. H-Gate-2b asserts convergence directly.

### H2 — the top-level action table (`plugins/sdlc/commands/loop.md`, ai-enablement-engineer)

`commands/loop.md` keeps argument parsing, Step 0 (review-config read), Step 1 (PR resolve), the budget call sites, the script invocation, **the clean guard**, and:

```text
eval "$(bash ${CLAUDE_PLUGIN_ROOT}/scripts/loop-decide.sh <PR> "$REVIEW_PATH" "$dir" "$REVIEW_MARK")"

DECISION=wait   -> loop-budget.sh check "$HEAD" "$UNRESOLVED" [--grace iff GRACE=yes]
                   RE_REQUEST=yes AND REVIEW_MODE=on-update -> gh pr edit <PR> --add-reviewer @copilot
                   exit 0 -> schedule next iteration; exit 1 -> stop, print BUDGET_REASON + BLOCKED_BY
DECISION=fix    -> /review-fix <PR> INLINE (session model); on error or `Status: blocked` -> HALT
                   on-create -> stop after this single fix; on-update -> schedule next iteration
DECISION=review -> REVIEW_CMD INLINE (session model); write REVIEW_MARK; loop-budget.sh check; schedule
DECISION=clean  -> ASSERT clean-guard (H3) ELSE treat as DECISION=halt
                   run --on-clean exactly once (if provided), then STOP (success)
DECISION=halt   -> print RULE, FIELDS, BLOCKED_BY; do NOT schedule a next iteration
DECISION absent / not in enum / RULE not in enum -> re-run the script ONCE; second failure -> HALT
```

### H3 — the clean guard (`commands/loop.md`, ai-enablement-engineer)

`DECISION=clean` is the **only** decision with an irreversible consequence: it runs `--on-clean`, which under `/auto` is the auto-merge. The orchestrator does not take it on trust — it re-evaluates the predicate from the individual integers in `FIELDS`:

```text
clean-guard(copilot)    := reviewed-head==1 AND changes-requested==0 AND unresolved==0
                           AND checks-failing==0 AND checks-pending==0
clean-guard(in-session) := reviewed-head==1 AND review-clean==1 AND unresolved==0
                           AND checks-failing==0 AND checks-pending==0
guard fails, or any named field is absent/non-numeric -> DECISION=halt; print
   "clean guard rejected a clean decision on <head> — <FIELDS>"; STOP.  # never fall through to --on-clean
```

Cost: five integer comparisons on values already in the block. The guard is **not** a substring match on the returned blob — it parses each named field and compares it. A `grep -q clean` over the output would pass on the string "not clean"; this epic has already shipped four dead assertions of exactly that shape.

The guard remains worthwhile with a script: it costs ≈ 250 B, it is the containment that makes an un-reverted transcription bug non-catastrophic while a revert lands, and it is independent of the table it checks. Rule 4 was already self-contained in the fast path (D7); H keeps only its predicate there and ports its prose.

| `loop-status` line absent, unparseable, or a named field non-numeric | `RULE=unresolvable`, `DECISION=wait`, reason in `BLOCKED_BY`. **Never** clean, **never** halt. Bounded by `loop-budget.sh`. |
| Probe resolved but no rule matched | `RULE=7`, `DECISION=halt` — today's catch-all, unchanged. No state falls off the table silently. |
| `loop-decide.sh` emits a malformed block, or `DECISION`/`RULE` outside its enum | Re-run the script **once**; a second malformed block → **HALT** with the raw stdout printed. Never infer a decision from prose. |
| `loop-decide.sh` exits non-zero | Contract violation (it must always `exit 0`). Treat exactly as a malformed block: re-run once, then HALT. Never as `clean`. |
| `DECISION=clean` but the clean guard rejects it | Treat as `halt`. `--on-clean` does not run. Print the guard's message and `FIELDS`. **The single most important row in this table.** |
| `FIELDS` absent or a guard field non-numeric | Guard cannot evaluate → `halt`. Never default a missing field to a clean-compatible value. |
| stdout exceeds the 600 B cap | Not a run failure — the named fields still parse; record `returnCapExceeded: true`, which fails the pilot. A capped contract that grows is a contract that has started carrying prose. |
| Script cannot reach `gh` / network | `pr-loop-status.sh` is best-effort and prints zeros; that tuple selects rule 2a (wait) exactly as today. Unchanged behaviour. |
| `commands/loop.md` improvises the table inline after a script failure | Forbidden. The table no longer lives at the top level; improvising it is precisely the drift H-Gate-2 exists to prevent. The specced response is HALT. |
| Cache-read ratio falls below 94% on the pilot | **Revert per H4. Never trade the guardrail for instruction surface** (AC-3, verbatim from the epic). |

## Blast radius of a wrong decision

The mechanism change collapses the *probability* side of this table — a script cannot mis-decide relative to its own table, and the table is gate-pinned to the pre-change one. What remains is a transcription bug in the bash port. The *consequences* are unchanged, so they are enumerated in full. `AS` = actual state; `RET` = what the script returned.

| AS → RET | What happens | Cost | Recoverable? |
| --- | --- | --- | --- |
| clean → wait | Loop spins; the idle budget (1200 s) or the 30-pass backstop stops it | ≤ 30 wasted passes; PR left open | **Yes** — bounded by `loop-budget.sh`; human merges |
| clean → fix | `/review-fix` runs with nothing to fix; HEAD usually does not move; budget bounds it | one wasted session-model fix round | **Yes** |
| clean → halt | Loop stops on a converged PR | one manual merge | **Yes** |
| fix → wait | Unresolved comments sit unaddressed until the budget trips | ≤ 20 min latency | **Yes** |
| fix → halt | Loop stops with actionable feedback outstanding | manual `/review-fix` | **Yes** |
| wait → fix | `/review-fix` runs against an unreviewed HEAD; may push a no-op commit | one wasted round + a HEAD move that resets the review | **Yes** |
| wait/fix/halt → **clean** (unreviewed HEAD) | `--on-clean` would merge an **unreviewed** PR | severe | **Blocked by the clean guard** (`reviewed-head==1`) |
| fix → **clean** (unresolved comments) | `--on-clean` would merge over open review threads | severe | **Blocked by the clean guard** (`unresolved==0 AND changes-requested==0`) |
| halt(rule 6) → **clean** (red CI) | `--on-clean` would merge with required checks failing | severe | **Blocked by the clean guard** (`checks-failing==0`); branch protection is a second backstop |
| any → halt on a state that should wait | Loop stops early | manual restart | **Yes** |
| `pr-loop-status.sh` itself returns wrong integers | Script and guard consume the same wrong input | severe | **Not** addressed by H — that script is unchanged and out of scope |

**Summary.** Every recoverable class is bounded by the existing budget and costs at most one wasted round or ≤ 20 minutes. Every severe class routes through `DECISION=clean`, and every severe class is refused by the clean guard unless the probe script's own integers are wrong — which H does not change and cannot make worse.


The two caps guarantee a floor of **−4,044 B** on `loop.md` and **−9,395 B** combined; the item table's caps give the tighter **≤ −9,946 B** design target. Report both — the CI constant is the promise, the design target is the intent.

**Counted honestly against the win:** the script's stdout (≤ 600 B) lands in the transcript each pass, where today's `loop-status:` line (≈ 180 B) already does — a **+420 B per-pass tool-result delta**. Netting it against −9,946 B of instruction surface leaves ≈ **−9,526 B per pass**.

Against the programme endpoint of ≤ 230,000 tokens instruction load, H contributes ≈ **−9,946 B (≈ −2,490 tok) per loop pass**, multiplied by the passes in a story, plus the removal of 66.65 M resident tokens (1.52% of top-level) from *any* model tier — a script pays no per-token rate at all.

**The requests carve-out granted for Note 1 is no longer needed by H.** With a script there is no dispatch: H adds **zero** requests per pass and plausibly removes some (the pass no longer needs a model turn to read a table and reason over it). The carve-out — request *count* only, every token and resident guardrail unchanged, delta reported not suppressed — is recorded here as granted precedent (founder ruling for workstream E: "more requests are okay as long as the total token count decreases significantly") and remains available to a successor. H's pilot still **reports** its request delta rather than suppressing it, and expects it to be ≤ 0.

## Measurement, gates, and the pilot

**The correctness claim is not runtime-bound.** The decision function is deterministic over a 1,458-case finite domain, and the shipped artifact is the thing under enumeration — so equivalence is *proven*, not sampled, before the PR merges. This is the first workstream on this epic that can prove its own correctness pre-ship, and the mechanism change strengthens rather than weakens that.

**The spend claim is still runtime-bound.** Two independent reasons, same shape as NA-87/88/90/91/92:

```text
H changes the loop pass's own contract -> the shipping run's loop executes the PRE-change contract
plugins/** edits do not affect running agents -> they read CLAUDE_PLUGIN_ROOT (the cache), not the repo
```

Every runtime row on the implementation run's own transcript is therefore **NOT CAPTURED** with a named successor pilot. Do not estimate it.

## Open Questions

- [ ] **Rules 1, 5, 6, 7 have zero production evidence.** The golden encodes what the markdown says, not what a real PR has ever done. Should H additionally hand-construct a live PR state that exercises rule 6 (required check failing, no unresolved comments) before shipping? — **Suggested default: no, and say so in the PR body.** Constructing a red-CI PR to exercise a halt path is a manual test of behaviour H does not change; the honest mitigation is the `rulesWithZeroEvidence` assertion in H-Gate-3, which keeps the limitation visible on every run rather than letting a green gate imply coverage.
- [ ] **`--from-status` / `--from-fields` are test surface shipped in a production script.** H-Gate-2b guards against a bifurcated implementation, but the flags stay reachable in production. — **Suggested default: keep them, documented in the script header as test-only.** The alternative — a separate harness re-implementing the table — is the exact dead-code failure H-Gate-2b exists to prevent. `docs-sync-gate.sh` needs no analogous flag because its inputs are fixtures on disk; H's inputs are a live probe, so an injection point is the only way to make the gate exhaustive.
- [ ] **Should H-Gate-1/2/2b be wired into `.github/` in this story rather than left author-run?** They need no model and no transcript corpus, unlike every prior gate on this epic. — **Suggested default: author-run in H**, matching NA-91 D7 and NA-92 and keeping `.github/**` out of H's path scope; promote in a follow-up so the CI change is reviewable on its own.
- [ ] **The clean guard duplicates rule 4's predicate at the top level.** It costs ≈ 250 B of the capped stub and is, strictly, redundant once H-Gate-2 proves table equivalence. — **Suggested default: keep it.** It is the only runtime containment for the severe class while a revert lands, it is independent of the table it checks, and it is cheap. Dropping it would buy 250 B and remove the reason a transcription bug cannot merge an unreviewed PR.
