# Eliminate duplicate reads in pipeline — Technical Spec

**Story:** NA-88 — Eliminate duplicate reads in pipeline (5 pts)
**Epic:** NA-76 — SDLC token and cost optimisation programme (workstream **C**, 6.9% of the programme's projected cut, Phase 1)
**Feature:** PRD referenced from the NA-76 Epic (`docs/features/2026-07-30-sdlc-token-cost-optimisation-programme.md`) — Jira is the product-context source for this spec
**Base:** `develop` @ `0a905ff` (post-NA-86 PR #207 and post-NA-87 PR #209)
**Date:** 2026-07-31

## Overview

Stop the SDLC pipeline paying twice for the same file: add a binding "content already in your
transcript — do not re-read" clause to the domain-agent contract, carry a deterministic phase
context ledger across the PE Step 4 → QA Step 3 handoff so a fix agent is told the file set instead
of rediscovering it, and make the `SDLC agent reuse` decision observable so its claimed saving can
be verified rather than assumed.

**Non-goal restated for implementers:** nothing about *what* content an agent reads changes — only
whether the same path is read twice inside one transcript. A change that reduces reads by making an
agent skip context it actually needs is a regression, not a saving.

### Measured baseline (60 most recent transcripts of this project, 2026-07-31)

Read-call classification, per transcript, by what the same path's earlier read already delivered:

| Class | Calls | Share | Addressable by C? |
| --- | --- | --- | --- |
| First read of the path | 433 | 83.0% | No — unavoidable |
| Redundant: any read after a whole-file read of the same path | 58 | 11.1% | **Yes — the target** |
| Window overlapping an earlier window of the same path | 12 | 2.3% | Partly |
| Window disjoint from every earlier window | 19 | 3.6% | No — legitimate |
| Total | 522 | 100% | |

Of those repeats only **12 (2.3%)** are byte-identical argument repeats; the rest are a whole-file
read followed by a narrower one, or a narrower read followed by a whole-file one. Both re-bill
content the transcript already holds.

By file category (repeat share of that category's reads): source/other 19% (216 reads), self-generated
artifact 22% (59), plugin instruction 18% (158), project config + memory 7% (89). The single worst
observed path was a plan doc read **8×** in one session — the Epic's "a plan doc is loaded ~9× per
story" finding, reproduced.

**Honest correction to the Epic's headline.** NA-76 states "19% of Read is the same path re-read
within one transcript"; this spot check reproduces 17.0% same-path repeats, but 3.6 points of that
are disjoint windows that are not waste. C's addressable class is therefore **11.1% strictly
redundant + up to 2.3% overlapping**, not 19%. Authoritative per-story numbers come from C5's
analyser, never from a hand count (`tools/sdlc-analyser/README.md` escalation rule); this table is
call-count only — token weight is C5's output, and is deliberately not estimated here.

### Request / Response Shapes

```typescript
interface PhaseLedger {
  phase: number;
  agent: string;
  planSection: string | null;
  startSha: string;
  endSha: string;
  filesChanged: string[];
  filesRead: string[];
}

interface DuplicateReadReport {
  label: string;
  sessions: number;
  totalReads: number;
  firstRead: number; // no earlier read of this path in this transcript
  redundantAfterWhole: number; // any read after a whole-file read of the same path
  overlappingWindow: number; // window intersecting an earlier window of the same path
  disjointWindow: number; // window not intersecting any earlier window — legitimate
  redundantShare: number; // redundantAfterWhole / totalReads, 0..1
  byCategory: DuplicateReadCategory[];
  topPaths: DuplicateReadPath[];
}

interface DuplicateReadCategory {
  category: "plugin-instruction" | "self-generated-artifact" | "project-config" | "source-other";
  reads: number;
  redundant: number;
}

interface DuplicateReadPath {
  path: string;
  reads: number;
  redundant: number;
}
```

The ledger's wire form in a dispatch prompt is one `KEY=value` per line (same shape as
`branch-inventory.sh` and `worktree-setup.sh`), so a prompt never carries JSON:

```text
LEDGER_PHASE=2
LEDGER_AGENT=ai-enablement-engineer
LEDGER_PLAN_SECTION=## Phase 2 — Artifact templates · `ai-enablement-engineer`
LEDGER_FILES_CHANGED=plugins/sdlc/refs/domain-agent-handoff.md,plugins/sdlc/refs/qa-engineer-playbook.md
LEDGER_FILES_READ=plugins/sdlc/refs/principal-engineer-playbook.md
```

**The read-classification rule** (stated here because an unstated rule makes before/after
non-reproducible — same discipline as the padded-row and content-contract rules in
`tools/sdlc-analyser/README.md`). Within one transcript file, for each `Read` tool-use in file
order, with `whole := offset == null AND limit == null` and a window's extent taken as
`[offset ?? 1, (offset ?? 1) + (limit ?? 2000) - 1]`:

```text
no earlier read of this path -> first read
any earlier read of this path was whole -> redundant                 # the whole file is already in the transcript
this read is whole AND an earlier read of this path exists -> redundant   # supersedes the earlier window, re-bills it
window intersects an earlier window of this path -> overlapping
otherwise -> disjoint                                                # legitimate: a new region of a file read in parts
```

first-match-wins, top to bottom. Subagent transcripts are separate files and therefore separate
transcripts — a path read by the orchestrator and again by a subagent is **not** a duplicate, because
the subagent's context genuinely does not hold it.

## Backend Implementation

### Phase 1 — `tools/` (platform-engineer)

Stack rules that bind: POSIX-portable bash / stdlib-only Python 3, must pass
`bash tools/portability-lint.sh`, read-only, never wired to mutate the repo. Follow the existing
`KEY=value`-per-line output shape and the README escalation rule — the tool is an aid; a written
manual reconciliation wins and goes in the PR body.

1. **`duplicate-reads.py` (C5)** — implements the read-classification rule above. Mirrors
   `cache-analysis.py`'s CLI shape: positional `<label>` then transcript paths, `--per-story`
   grouping by the story key parsed from each record's `gitBranch`, plus `--json` emitting
   `DuplicateReadReport`. Path→category mapping uses the four `DuplicateReadCategory` values, derived
   from the path, with `plugin-instruction` matching both `plugins/sdlc/` and a resolved plugin-cache
   path. If no given path resolves to a readable file, fail with the paths tried and exit 1 — never
   emit a zeroed report that reads like a real empty result (`cache-analysis.py` precedent).
2. **`artifact-contract.sh` matching semantics (C7)** — two changes, both to comparison only; the
   extraction rule and the `--section`/`--fence` selectors are unchanged:
   - **Ordered subsequence, not strict position.** The template's contract items must appear in the
     artifact **in order**; artifact-side items the template does not name are skipped, not treated
     as a mismatch. A produced artifact is legitimately a superset of its template.
   - **Placeholder-normalised comparison.** Before comparing a heading or literal, normalise
     template placeholders — bracketed `[...]`, angled `<...>`, and the bare ordinal tokens `N` and
     `NNNN` — to a wildcard, then match the whole normalised string. `## Phase N — [Domain] [agent-name]`
     must match `## Phase 1 — Tooling / measurement instrument · \`platform-engineer\``.
   - Regression proof: NA-87's five tier-1 reference artifacts must still report `CONTRACT_MATCH=true`
     (subsequence matching is a superset of exact matching), and a deliberately dropped heading must
     still report `CONTRACT_MATCH=false`. Both go in the tools' own test coverage.
3. **`README.md` (C5, C7)** — add a `duplicate-reads.py` section carrying the classification rule
   verbatim, and update the content-contract section to state the subsequence + placeholder rules.
4. **`.github/workflows/ci.yml` (C6)** — one line, `- run: bash plugins/sdlc/scripts/__tests__/context-reuse.test.sh`,
   alongside the existing per-test lines.

### Phase 2 — `plugins/sdlc/` (ai-enablement-engineer)

Conventions that bind: `plugins/sdlc/**/*.md` is prettier-ignored with unpadded tables (ADR 0016);
procedural sections use lean pseudocode per ADR 0017 and `refs/pseudocode-notation.md`; every
converted file keeps its one-line notation header.

1. **C1 — `refs/domain-agent-handoff.md`, new `## Context reuse` section.** Placed after
   `## Branch and PR — do not create` and before `## Memory write (before committing)`, so it is read
   before any work starts and does not disturb NA-87's re-encoded section. Budget **≤ 900 bytes**
   (≈240 est tok). It must state, as pseudocode plus one annotation line each:
   - The rule: a path already read **in full in this transcript** is never read again.
   - Read-after-edit is never a verification step — `Edit`/`Write` fail loudly, so a successful edit
     needs no confirming read.
   - Widening rule: when an earlier read was windowed and another region is needed, read **only the
     missing region** with `offset`/`limit`; never re-read the whole file.
   - The three carve-outs, stated as explicit exceptions so the clause cannot be over-applied:
     (a) a git operation (`checkout`, `merge --ff-only`, `fetch` + reset) changed the tree since the
     read; (b) the earlier read was reported truncated; (c) the earlier read happened in a
     **different transcript** — a freshly dispatched agent's context is empty and the ledger names
     paths, it does not supply their content.
   - The precedence line: correctness wins. If the agent cannot establish the current content of a
     file it must edit, it reads it — an unnecessary read is cheap, a wrong edit is not.
2. **C2 — pointer lines.** One ≤200-char line added as item 13 of the PE Step 4 prompt contract and
   item 10 of the QA Step 3 dispatch list, each naming
   `${CLAUDE_PLUGIN_ROOT}/refs/domain-agent-handoff.md`'s `## Context reuse` section. Canonical text
   lives in exactly one place (ADR-0004); the pointers never restate the rule.
3. **C3 — phase context ledger.** PE Step 5 already captures pre-dispatch HEAD for the HEAD-advance
   check; extend it to record `startSha`/`endSha` and emit the phase's `LEDGER_*` block. PE Step 6's
   hand-off list gains the ledger set. QA Step 3 includes the matching row in every fix dispatch,
   fresh or reused, before the findings. Persistence and fallback, stated as pseudocode:

   ```text
   ledger_file := $(bash ${CLAUDE_PLUGIN_ROOT}/scripts/tmp-dir.sh)/phase-ledger.txt
   PE Step 5 -> append this phase's LEDGER_* block to ledger_file
   QA Step 3, ledger_file readable -> select the row whose LEDGER_AGENT matches the dispatch target
   QA Step 3, ledger_file absent -> reconstruct: git -C "$WORKTREE" diff --name-only BASE_SHA..origin/<BRANCH_PREFIX>/<STORY-KEY>, group by the project-context workspace->agent table   # a fresh session after Step-7 teardown has no temp dir
   reconstruction fails -> dispatch without a ledger   # never a STOP: the ledger is an optimisation, not a contract input
   ```

   The ledger file lives in the session temp dir, never in `$WORKTREE` — a file there would trip the
   Step-5 and Step-6 stray-file guards.
4. **C4 — reuse observability.** QA Step 3's reuse branch records, per fix round,
   `REUSE=true|false` and a one-token reason (`reused`, `fallback-session-boundary`,

### Why tier 1 could not have caught this — the self-confirming reference artifact

NA-87's tier-1 gate scored **5/5 `CONTRACT_MATCH=true`** while real artifacts of the same two types
score 1/18 and 2/4. Both numbers are honest; they measure different things. The five reference
artifacts were authored by the same agent, in the same dispatch, from the same template, for the
express purpose of matching it — so they reproduced the template's heading sequence exactly, never
inserted a section of their own, and copied the instruction parentheticals verbatim. A real artifact
does none of those things.

**The general rule, which is the transferable part:** a reference artifact generated by the agent
that authored the template is **self-confirming** — it validates that the agent can copy its own
template, which was never in doubt, and it cannot validate the instrument, because it is constructed
to avoid every input shape the instrument mishandles. It is a useful smoke test and a genuine guard
against a *dropped* section; it is not a gate.

A real gate diffs the template against a **genuine artifact produced by an independent run** — a
different agent, a different dispatch, with the artifact's content driven by the story rather than by
the desire to match. Where no such artifact can exist before merge (NA-87's actual constraint), the
honest construction is tier 1 as a smoke test **plus** a named, scheduled tier 2 against real output
— which is exactly what D12 did, and why this defect was found one story later rather than never.
The failure was not the two-tier design; it was reporting tier 1's 5/5 without stating what it could
not detect. D11 carries the standing consequence for workstreams D–H.

### Interpreting the result

Dry-run at spec-authoring time against merged artifacts, the matcher reports
`CONTRACT_ARTIFACT=1 / CONTRACT_MATCH=false` for `docs/superpowers/specs/NA-87.md` and
`CONTRACT_ARTIFACT=2 / CONTRACT_MATCH=false` for `docs/superpowers/plans/NA-87.md`. Two independent
causes, neither of which is an NA-87 content regression:

1. **Positional matching does not resynchronise.** Inserting any artifact-side heading the template
   does not name (`## Scope map`, `## Global Constraints`, `## Validation gates`) aborts every
   subsequent match. Every real artifact does this. → C7's ordered-subsequence fix.
2. **Three template headings carry an instruction parenthetical** that no sane produced artifact
   copies. → C8's heading fix.

Recording only the as-found number would misattribute an instrument defect to NA-87's re-encoding.
Recording only the post-remedy number would hide that the instrument was wrong. **Both are recorded**,
in that order, with the interpretation line attached, for every one of the five rows.

**If a post-remedy row still reports a miss**, apply NA-87's D8 verdict unchanged: open a follow-up
PR that restores the missing item **in the template**; never loosen the tool to make a mismatch
disappear, and never revert NA-87 wholesale — a genuine miss is a one-line template fix and
reverting would also discard the verified work on the other templates.
