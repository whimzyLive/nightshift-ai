# Clear stale context on top-level sessions — Technical Spec

**Story:** NA-91 (workstream F of Epic NA-76, Phase 3, MED risk, 5 pts)
**Feature:** docs/features/2026-07-30-sdlc-token-cost-optimisation-programme.md
**Date:** 2026-07-31

Artifact encoding contract: unpadded tables, no section dropped, one-line N/A, verbatim contracts, rationale as annotation, prose < 10 lines between headings. plugins/sdlc/refs/artifact-encoding.md

## Overview

The top-level orchestrator session accumulates tool results that keep being re-billed on every later turn of the same session; 34.6% of top-level tool-result exposure is the post-PR-raise tail phase re-charging context produced before the PR existed. F evicts that context by ending the top-level session at the PR-raise boundary, so the review-fix loop starts from the instruction floor instead of inheriting the implementation phase.

## Mechanism survey — read this before designing

The story's AC-1 says "top-level session **context editing** clears stale tool results". Context editing in the API sense (`context_management.edits` / `clear_tool_uses_20250919`) is **not reachable from this repo** — this repo does not make the API calls; the Claude Code harness does. Verified against the local build (`~/.local/share/claude/versions/2.1.220`, read-only string/AST probe):

| Lever | Repo-drivable | Clears resident tool results | Evidence |
| --- | --- | --- | --- |
| API `context_management.edits` | No | Yes | The only `clear_tool_uses_20250919` occurrences in the build are inside the bundled `claude-api` **skill documentation**, not call sites. The repo never constructs the request. |
| Harness microcompact (`compact_micro_keep_recent`) | No | Yes | Real implementation, but fires only from the server-driven `context_hint` reject path (`handleHintReject` → `applyHintEdits` → `qsd`), with a hardcoded `keepRecent` and a `tokensSaved < 20000 → return null` floor. No setting, env var, or slash command exposes it. |
| `PostToolUse` hook rewriting a tool result | No | No | `hookSpecificOutput` for `PostToolUse` accepts `additionalContext` only. `updatedInput` is documented **PreToolUse only**; `updatedOutput`, `updatedToolResult`, `toolResultOverride` have **0 occurrences** in the build. A hook can add context, never shrink it. |
| `PreToolUse` `updatedInput` | Yes | No — prevents, never clears | Proven by NA-89's `.claude/hooks/rtk-line-scan.sh`. Bounds what enters; cannot evict what already entered. |
| Ending the top-level session at a defined boundary | **Yes** | **Yes — everything before the boundary** | `plugins/sdlc/scripts/session-complete.sh` already releases the session and already carries the PR URL in its marker (`<<<SDLC_SESSION_COMPLETE:KEY\|PR=URL>>>`). |

**Decision.** F ships as a **session-boundary reset**, not a context-editing configuration. This is the only repo-owned mechanism that actually clears. AC-1's staleness rule is therefore expressed over session lifetime rather than over an in-session clock — see "Staleness rule" below. This is a deviation from the ticket's literal wording and is called out for the review gate.

## Sizing — re-derived, not inherited

**Corpus rule (stated because the population choice is the whole argument):**

```text
TOP-LEVEL := <project>/*.jsonl                              # the orchestrator's own transcript — F's population
SUBAGENT  := <project>/<session>/subagents/**/agent-*.jsonl # RECURSIVE; C and E's population
project   := ~/.claude/projects/-Users-Rushi-Development-EdgeTech-ai-workspace-nightshift
filter    := session contains a real /sdlc:* invocation AND >= 20 assistant turns
```

Path lists built with Python `pathlib.glob`; **never** parsed `ls` (the rtk hook size-annotates `ls` output, which silently corrupts path lists).

**Correction to inherited figures — the 798 reads were not an artifact, they were F's population.** NA-90 found NA-88's baseline had captured 798 of 6,793 reads via a non-recursive glob and called it a miss. Re-derived here: top-level Reads = **798 exactly**; recursive subagent Reads = **6,060**; total **6,858**. NA-90 is right that 798 is the wrong population for C and E. It is the *exactly correct* population for F. F's sizing rests on the corpus that story labelled an artifact, and that is not an error.

**Second correction — the recursive rule itself under-captures.** `<session>/subagents/agent-*.jsonl` returns 553 files; `rglob("agent-*.jsonl")` returns 1,443. The missing 890 sit under `<session>/subagents/workflows/wf_*/agent-*.jsonl`. Any successor measuring C or E must recurse through the `workflows/` tier.

**Why eviction and not bounding, for the dominant 79.9%.** Top-level Reads are dominated by instruction files the orchestrator must execute end-to-end — playbooks, the plan doc, the spec. E's own carve-out already rules these out of bounding (`the file IS the instruction you must execute -> read whole`). Shrinking them is workstream A's job. The only remaining lever on top-level reads is to stop re-billing them once the phase that needed them has closed. That is F.

**The boundary, measured (n = 43 top-level sessions that raise a PR):**

| Quantity | Value |
| --- | --- |
| Turns occurring after the first PR raise | median 43.3% of the session |
| Exposure the post-PR-raise tail inherits from before the boundary | **34.6% pooled** (median 49.6% per session, p25 31.1%, p75 57.2%) |

Alternative horizons, for the review gate to weigh (share of top-level tool-result exposure recoverable):

| Rule | Recoverable |
| --- | --- |
| clear results older than 5 turns | 98.7% |

The turn-horizon rules recover more but are **unimplementable** — they need the context-editing surface the mechanism survey rules out. F takes the largest recoverable share available to a repo-owned mechanism.

## Backend Implementation

### Staleness rule (satisfies AC-1)

```text
stale := a tool result whose producing phase has closed
phase closes -> the phase's PR has been raised AND its Jira comment posted
boundary action := release the top-level session; the review-fix loop runs as a NEW top-level session
```

Rationale as annotation: the PR-raise turn is the one point in every phase where all preceding work is already durable on a branch and in Jira, so nothing resident is still load-bearing. It is also mechanically observable in a transcript (first `raise-pr.sh` or `gh pr create` call), which is what makes the gate falsifiable.

### F1 — Move the release before the tail loop (`plugins/sdlc/**`, ai-enablement-engineer)

Today every top-level command ends with "the loop is the tail — it owns the single `session-complete`". F inverts that: the command releases at PR-raise, and the loop is re-entered as a fresh session.

| File | Change |
| --- | --- |
| `plugins/sdlc/commands/auto.md` | "Loop-after-raise + mode-conditioned terminal action" (§ "The procedure"), A1, A2/A3, B1/B2 — release after step 3 (Jira comment), then emit the loop re-invocation instead of running it inline |
| `plugins/sdlc/commands/impl.md` | Final-action section — same inversion |
| `plugins/sdlc/commands/spec.md` | "Final action — loop the PR to Copilot-clean, then release" — same inversion |
| `plugins/sdlc/commands/plan.md` | Final-action section — same inversion |
| `plugins/sdlc/commands/review-fix.md` | No change — it runs no tail loop; its `Final action` release already fires only when it is the top-level command |
| `plugins/sdlc/scripts/session-complete.sh` | No change — it already accepts `<pr-url>` and emits `\|PR=URL` |

**No new harness protocol is required.** The marker already carries the PR URL, so a harness that today watches for release and re-invokes on the next phase can re-invoke `/loop /sdlc:loop <PR_URL> --phase <GATE_PHASE>` from the same signal.

Interactive (non-harness) sessions have no re-invoker. Gate the behaviour so interactive UX does not regress:

```text
SDLC_SESSION_KEY set   -> harness-driven -> release at PR raise; harness re-invokes the loop
SDLC_SESSION_KEY unset -> interactive    -> print the exact re-invocation line, then release
```

`scripts/session-key.sh` already resolves this variable — first-match-wins, no new detection logic.

### F2 — Residency instrument (`tools/**`, platform-engineer)

`tools/sdlc-analyser/context-residency.py`, following `read-bounding.py`'s existing CLI and JSON conventions.

```text
usage: context-residency.py <label> (<transcript.jsonl>... | --corpus-list <file>) [--boundary pr-raise|none]
```

Emitted JSON fields (verbatim contract):

| Field | Meaning |
| --- | --- |
| `topLevelTranscripts` | corpus partition count — same convention as `read-bounding.py` |
| `subagentTranscripts` | corpus partition count; F expects 0 and reports non-zero rather than silently mixing |
| `toolResultExposure` | byte-turns, summed |
| `boundaryTurn` | assistant-turn index of the first `raise-pr.sh` / `gh pr create`; `null` when absent |
| `inheritedExposure` | byte-turns of pre-boundary results billed after `boundaryTurn` |
| `inheritedShare` | `inheritedExposure / toolResultExposure`, `0.0` when `boundaryTurn` is `null` |
| `cacheReadRatio` | `cache_read / (cache_read + cache_creation + input)` — the AC-2 guardrail |
| `skippedLines` | unparseable JSONL lines, counted not swallowed |

### F3 — Falsifiability harness (`tools/**`, platform-engineer)

`tools/sdlc-analyser/__tests__/context-residency.test.sh`, mirroring `read-bounding.test.sh`. **Gate-2 requirement (the D11 mirror): the metric must reach both ends.** Two hand-authored fixtures:

| Fixture | Asserts |
| --- | --- |
| `no-boundary.jsonl` | session with no PR raise -> `boundaryTurn: null`, `inheritedShare: 0.0` |
| `full-inherit.jsonl` | all results pre-boundary, all turns post-boundary -> `inheritedShare: 1.0` |

A metric that can only ever report one value is not evidence. These two fixtures prove `inheritedShare` can reach 0.0 **and** 1.0.

## Error Handling

| Scenario | Behaviour |
| --- | --- |
| Harness does not re-invoke the loop after release | PR stays open, unreviewed. Detectable: the Jira comment is already posted before release, so the phase is auditable. Mitigation is the interactive fallback line, printed unconditionally. |
| `SDLC_SESSION_KEY` unset and founder does not re-run | Same as today's manual-merge path; no regression versus a halted loop. |
| `context-residency.py` given a subagent transcript | Report it in `subagentTranscripts` and continue; never silently pool the two populations. |
| Unparseable JSONL line | Skip, increment `skippedLines`, exit 0. |
| `boundaryTurn` absent (no PR raised) | `inheritedShare: 0.0`, not an error — a spec/refine session legitimately raises no PR. |
| Cache-read ratio falls below 94% on the pilot | **Revert or re-sequence F. Never trade the guardrail for a smaller instruction surface** (AC-2, verbatim). |

## Measurement, gates, and the pilot

**F cannot be measured by the run that ships it.** Same shape as NA-87, NA-88 and NA-90. Two independent reasons:

```text
F changes the orchestrator's own session model -> the shipping run executes on the PRE-change contract
plugins/** edits do not affect running agents  -> they read CLAUDE_PLUGIN_ROOT (the cache), not the repo
```

So the implementation run's own transcript is **NOT CAPTURED** for every runtime row. Do not estimate it.

**Named successor pilot: the first `TRIAGE=full` story run end-to-end through `/sdlc:auto` after (a) NA-91 merges to `develop` and (b) the sdlc plugin is released and the cache updated at the new version.** The pilot must be a story NA-91 does not author. Record its key in the merged PR body per AC-4.

Gate ladder, with what each can and cannot detect:

| Gate | Instrument | Can detect | Cannot detect |
| --- | --- | --- | --- |
| G1 — text present | `context-residency.test.sh` | that the author wrote what the author intended | whether any session obeys the boundary. **Smoke test, never a gate** (NA-88 D11 — same story authors tool and fixtures) |
| G2 — falsifiable | the two fixtures above | that `inheritedShare` reaches both 0.0 and 1.0 | anything about real sessions |
| G3 — pilot | `context-residency.py` on the pilot's top-level transcript | `inheritedShare` collapsing toward 0.0; `cacheReadRatio`; avg/peak resident | one run cannot move AC-1's dollar figure (8-pt IQR $68.72) |

Pilot pass conditions (all must hold):

```text
ASSERT inheritedShare on the pilot < 0.10          # baseline pooled 0.346, median 0.496
ASSERT cacheReadRatio >= 0.94                      # baseline 96.64%, predicted -0.06 pp
ASSERT avg resident not increased AND peak resident not increased
ASSERT requests, QA rounds, blocked rate, review findings, loop passes all not increased
ELSE revert or re-sequence — never trade the guardrail for instruction surface
```

**Cache-guardrail prediction, quantified.** One extra boundary per story adds one cold instruction-floor cache-write (median first-write 28,932 tok, p75 45,326). Modelled over the 86-session corpus: **96.64% -> 96.59%, a -0.06 pp change against 2.64 pp of headroom.** Two boundaries: -0.11 pp. The story names cache regression as F's primary risk; the arithmetic says the risk is small but it is still the pilot's binding metric, because the model assumes the tail segment retains enough turns to amortize (median 43.3% of turns is post-boundary, so it does).

**AC-5 (the 7.0% cut-rate) stays uncounted** until the pilot passes every gate, per Epic comment "E / F / G cut-rates are judgement, not measurement". This spec deliberately does **not** claim 7.0%; it claims 34.6% of top-level tool-result exposure, which is a different and directly measured quantity.

## Out of Scope

- Any prompt-caching change — out of scope programme-wide.
- Editing `refs/domain-agent-handoff.md`, `## Context reuse`, or `## Bounded reads` — C and E own those; both are byte-pinned.
- API-level context editing or harness microcompact configuration — not reachable from this repo (mechanism survey).
- Spill-to-file for top-level Bash output (10.7% of top-level exposure) — that is prevention, not clearing; propose as a separate follow-up rather than widening F.
- Pushing top-level work into subagents — that is workstream G (NA-92 or successor), not F.
- Turn-horizon staleness rules (94.8% at H=20) — higher yield, no implementable mechanism.
- CI wiring for `context-residency.py` — author-run, matching `artifact-contract.sh` (D7).
- Any change to `.github/` — platform-engineer surface, and F wires no CI.
