## Overview

Three units of work that the top-level orchestrator executes inline — the QA quality-gate run, the Step-7 AC/plan verification reads, and the Step-6.5 docs-sync gate — are relocated so their reads and command output land in a short-lived subagent (or a script) instead of the orchestrator's own transcript. The orchestrator keeps every decision those steps feed; only their raw input and output move.

## Backend Implementation

### The offload rule (satisfies AC-1)

```text
offloadable := a unit of work that (a) only reads or runs commands, (b) produces a verdict
               expressible in <= its stated return cap, and (c) never needs to dispatch an agent
offloadable -> execute in a dispatched `general-purpose` subagent (or a script when the unit
               carries no judgment at all); return the verdict, never the raw input
NOT offloadable -> stays at the top level, no exception:
   any decision that routes the run (pass/fail, clean/blocked, which of the five docs buckets)
   any dispatch of a domain agent            # one-level nesting limit, ADR-0012
   any attestation about the PRIMARY CHECKOUT # a subagent cannot attest to its own isolation breach
```

Rationale as annotation: a step whose full output must come back to the top level has not been offloaded, it has been round-tripped — one extra dispatch for the same resident bytes. Every unit below therefore carries an explicit **return cap**, and the cap is the thing CI and the pilot assert.

### G1 — QA quality-gate run (`plugins/sdlc/**`, ai-enablement-engineer)

`qa-engineer-playbook.md` Step 6 keeps its heading, the dispatch stub, and the failure routing. The run mechanics move to a new **`plugins/sdlc/refs/qa-gate-runner.md`**, named in the dispatch prompt and read only by the runner.

Moved into the runner: the `$WORKTREE` stray-file assert, `git fetch`/`merge --ff-only`, `cd "$WORKTREE"`, `export NX_CACHE_DIRECTORY`, the project-context Tooling + Quality Gate commands, the infra-stage build, and capture of their output.

Dispatch (verbatim shape):

```text
Agent({ subagent_type: "general-purpose",
        description: "Run quality gate",
        prompt: <STORY-KEY>, <WORKTREE>, <NX_CACHE_DIRECTORY>, <BRANCH_PREFIX>,
                "Follow ${CLAUDE_PLUGIN_ROOT}/refs/qa-gate-runner.md exactly. Return only the block it defines." })
```

Return contract (verbatim; **cap 2,000 B**):

```text
Gate: pass | fail
Commands: <one line per command actually run, exact string>
Evidence: <verbatim final status line(s) per command, truncated to 1,200 B — never paraphrased>
Failing workspace: <path or nx project name | none>
Owning agent: <agent-name from the project-context workspace->agent table | none>
Error: <first 400 B of the failing command's stderr, verbatim | none>
Stray files: <git status --porcelain output | none>
```

Top level still does, and must: read the block; on `Gate: fail` dispatch the owning domain agent with the `Error` verbatim (Step 3 protocol) and **re-dispatch a fresh runner** after the fix; on `Stray files` non-empty, STOP exactly as today; carry `Evidence` into the Step-8 `Quality gate:` line.

`Gate: pass` with an empty or absent `Evidence` is a contract violation → re-dispatch once, then return `blocked`. This preserves `verification-before-completion` (evidence, never assertion) while capping what the evidence costs.

### G2 — Step-7 AC + plan verification (`plugins/sdlc/**`, ai-enablement-engineer)

`qa-engineer-playbook.md` Step 7 keeps its heading, the dispatch stub, and the unmet-AC routing. Both checklists and the defect regression-evidence contract move to a new **`plugins/sdlc/refs/ac-verification.md`**.

Moved into the verifier: reading `docs/superpowers/plans/<STORY-KEY>.md`, `git log ${BASE_SHA}..origin/<BRANCH_PREFIX>/<STORY-KEY>`, per-AC file/test lookups, and on the defect path the phase-3-sha detached checkout, both regression-test runs, and their pasted output.

Return contract (verbatim; **cap 4,000 B, and <= 250 B per AC/task line**):

```text
Verification: complete | incomplete
AC-<n>: met | unmet — <path:line | test name | commit sha>          # one line per AC, always
Plan task <n>: met | unmet — <evidence>                             # full path only; omitted on lightweight
Regression evidence: fail-before <sha> / pass-after <sha> | n/a     # defect path only
Unmet: <comma-separated AC/task ids | none>
Owner: <id>=<agent-name>, ...  | none                               # owning agent per unmet id
```

Top level still does, and must: decide `clean` vs `blocked`; on any `unmet`, dispatch the named owning domain agent (Step 3 protocol) and re-run Steps 6–7; refuse `clean` while `Unmet` is non-empty; carry the `AC check:` line into the Step-8 verdict.

The verifier reads the plan doc **whole** — it is the instruction being verified against, which is E's own carve-out (`the file IS the instruction you must execute -> read whole`). G does not bound it; G moves it. Measured, that read is 13,092 B mean at top level today, and on the `/impl`/`/auto` path it is a *re-read* (PE Step 2 already read the same file), so G also removes one duplicate read on those paths. On `/review` and `/review-fix`, where PE never ran, it is a first read.

### G3 — Post-QA docs sync (`plugins/sdlc/**`, ai-enablement-engineer)

**State plainly: the docs sync itself is already dispatched to a subagent today** — `principal-engineer-playbook.md:543` dispatches the `knowledge-engineer` post-QA variant. AC-1's docs-sync clause is already satisfied at HEAD for the *work*. What still executes at the top level is the **gate that decides whether to dispatch**: the manifest resolution (`git show origin/<BASE-BRANCH>:.claude/project/docs-manifest.md`), the story-branch-vs-base changed-file set, and the activated-row scope resolution that requires reading `docs-pipeline-core.md` §3. Measured: 128 direct calls, 218,258 B, 4,750 B per impl session.

That gate carries **no judgment** — it is three deterministic set operations with a fail-safe default. It therefore becomes a script, **not** a dispatch: dispatching an agent to decide whether to dispatch an agent costs a whole subagent instruction floor to save a smaller one, and the change-size gate exists precisely to avoid an unnecessary dispatch.

New **`plugins/sdlc/scripts/docs-sync-gate.sh`**, following `dep-gate.sh`'s contract-line convention:

```text
usage: docs-sync-gate.sh <STORY-KEY> <BRANCH_PREFIX> <BASE-BRANCH>
stdout (exactly two lines, first-match-wins; cap 200 B):
  DOCS_GATE=skip-no-manifest | skip-no-tracked-files | dispatch | dispatch-unresolvable
  REASON=<one line>
exit 0 always   # the gate never halts the run; the orchestrator owns the consequence
```

```text
manifest absent at origin/<BASE-BRANCH>            -> DOCS_GATE=skip-no-manifest
changed-file set ∩ activated row scopes == ∅       -> DOCS_GATE=skip-no-tracked-files
changed-file set OR row scopes unresolvable        -> DOCS_GATE=dispatch-unresolvable   # FAIL SAFE
otherwise                                          -> DOCS_GATE=dispatch
```

Fail-safe is preserved verbatim from today's playbook: an unreadable probe resolves toward dispatching, never toward skipping.

Top level still does, and must: read two lines; map them onto the **unchanged five-bucket outcome table** (which stays in the playbook — it is the orchestrator's decision); own the WARN-vs-STOP split; snapshot/assert the primary checkout around the dispatch (`assert-workspace-clean.sh`); push from `$WORKTREE`; emit the Step-8 `Docs sync:` line. The primary-checkout guard **cannot** move — a subagent attesting that it did not corrupt the primary checkout is not evidence.

## Error Handling

| Scenario | Behaviour |
| --- | --- |
| `general-purpose` dispatch returns a malformed block (missing `Gate:` / `Verification:`) | Re-dispatch once with the contract restated; a second malformed return → QA returns `blocked`. Never infer the verdict from prose. |
| `Gate: pass` with empty `Evidence` | Contract violation → re-dispatch once, then `blocked`. A pass may never rest on assertion. |
| Runner exceeds its return cap (pastes the whole log) | Not a run failure — the orchestrator truncates and proceeds, but `returnCapExceeded: true` is recorded and **fails the pilot** (AC-3). A round-trip is the failure mode G exists to avoid. |
| Runner cannot `cd "$WORKTREE"` (torn down / GC'd) | Return `Gate: fail`, `Error: worktree missing`. Orchestrator re-provisions via `worktree-setup.sh` (idempotent) and re-dispatches once. |
| `docs-sync-gate.sh` cannot resolve the diff or the manifest rows | `DOCS_GATE=dispatch-unresolvable` → dispatch anyway. Fail safe, verbatim from today's playbook. |
| `docs-sync-gate.sh` non-zero exit | Treat as `dispatch-unresolvable`; never as `skip`. A gate that silently skips docs regeneration is worse than the overhead it saves. |
| Subagent attempts to dispatch an agent | Impossible by design (one-level limit). If a future harness allows it, the return contract still has no field for it — the orchestrator ignores anything it cannot parse. |
| Primary checkout mutated during a G1/G2/G3 dispatch | Detected by `assert-workspace-clean.sh` at the **top level**, unchanged. Hard STOP. Never delegated. |
| Unparseable JSONL in `work-placement.py` | Skip, increment `skippedLines`, exit 0. |
| `work-placement.py` resolves 0 T3 (`workflows/wf_*`) transcripts against a real corpus | Loud stderr WARNING naming the count; `--corpus-list` with any missing path → exit 1. |
| Cache-read ratio falls below 94% on the pilot | **Revert or re-sequence G. Never trade the guardrail for instruction surface** (AC-2, verbatim). |

## Open Questions
