### `plan-slice.sh` — CLI and stdout contract

```text
bash plugins/sdlc/scripts/plan-slice.sh <plan-path> phase <agent-name>
bash plugins/sdlc/scripts/plan-slice.sh <plan-path> checklist
```

Emits `KEY=VALUE` lines on stdout, one per line — the same shape as
`scripts/worktree-setup.sh` (`WORKTREE=`, `NX_CACHE_DIRECTORY=`, consumed at
`principal-engineer-playbook.md:249-250`) and `scripts/loop-decide.sh`
(`DECISION=`, `RULE=`, … asserted at `__tests__/loop-decision-budget.test.sh:40`).

Return contract, **verbatim**:

```text
MODE=phase|checklist
SLICE=<absolute path to the slice file, OR the plan path itself on fallback>
TASKS=<integer — count of task lines inside SLICE>
PHASES=<integer — phase headings matched in the whole doc; 0 in checklist mode>
GRAMMAR=matched|unmatched
```

Failure contract, **verbatim** (exit 2, and **no `SLICE=` key is emitted**):

```text
ERROR=plan-not-found|bad-mode|bad-args
```

| Exit | Condition | stdout |
| --- | --- | --- |
| 0 | usable output produced (including every fallback) | full 5-key block |
| 2 | plan path does not exist, unknown mode, or wrong arg count | `ERROR=` only |

## Grammar — pinned, and what happens when a plan does not match it

Pinned at `c47eba9` from `agents/tech-lead.md:138` (`## Phase N — [Domain] [agent-name]`) and
`:140` (`- [ ] [agent-name] <task>`), and validated against the real corpus.

```text
PHASE_HEADING   := ^## Phase <digits> (—|–|-) <text> \[<agent-name>\]$
DEPFREE_HEADING := ^## .*\bDEPENDENCY-FREE\b.*\[<agent-name>\]$        # tech-lead.md:99-102 form
SECTION_END     := next line matching ^##[^#] , or EOF
TASK_LINE       := ^\s*[-*] \[[ xX]\]\s
FENCE_RULE      := a ^## line inside a ``` or ~~~ fence is NOT a heading
agent-name      := the owner column of the project-context workspace→agent table
```

`FENCE_RULE` is load-bearing, not defensive: real plans quote the `tech-lead` template inside fenced
blocks (`docs/superpowers/plans/NA-93.md` embeds markdown examples), and a fence-blind scanner
truncates the slice at a fake heading.

**Multiple phases per agent are normal and MUST all be returned.** `NA-92.md` and `NA-93.md` each
assign two separate phases to one agent. Phase mode concatenates every matching section **in
document order** into one slice file. Returning only the first is a silent data loss.

### Fail-safe direction — always widen, never empty

| Condition | `GRAMMAR` | `SLICE` | `TASKS` | Exit | Consumer effect |
| --- | --- | --- | --- | --- | --- |
| ≥1 phase heading matches the requested agent | `matched` | tmp slice file | slice task count | 0 | agent reads its phase |
| Doc has phase headings, none for this agent | `matched` | **the plan path itself** | whole-doc task count | 0 | agent reads the whole plan |
| Doc has zero phase headings | `unmatched` | **the plan path itself** | whole-doc task count | 0 | agent reads the whole plan |
| Plan path does not exist | — | **not emitted** | — | 2 | orchestrator STOPs (matches `principal-engineer-playbook.md:96-97`) |

An empty slice is never a valid output. `TASKS=0` with a tmp-file `SLICE` is unreachable by
construction and, if produced, is an orchestrator STOP (see Error Handling).

**The unmatched path is not rare.** Measured over all 41 real plans at `c47eba9`: **30 match, 11 do
not** (`NA-4, NA-5, NA-53, NA-54, NA-55, NA-56, NA-57, NA-60, NA-61, NA-62, NA-69` — these use
`## Task N:` or `## Tier X` headings predating the current tech-lead grammar). 27% of the corpus
takes the fallback. It is a first-class path, gated as such (Gate G-10), not an edge case.

Note the fallback is still a **win**: it emits a *path* where today's instruction pastes *content*.
The paste→path move is the value; slicing is the bonus. The slicer failing to recognise a grammar
degrades NA-81 to its floor, never below today.

## Contract edits — exact intent (wording is the implementer's, byte cap is not)

**PE Step 4, before the dispatch block (`:313`):**

```text
slice := bash ${CLAUDE_PLUGIN_ROOT}/scripts/plan-slice.sh <plan-path> phase <agent-name>
exit 2 | TASKS==0 -> STOP; never dispatch a phase with no slice
```

`<plan-path>` is **resolved, not assumed.** On the `/impl` full path the plan is merged to
`<BASE-BRANCH>` and readable at `docs/superpowers/plans/<STORY-KEY>.md` from the primary checkout.
On the `/auto` Workflow-A path the plan doc is committed onto `feat/<STORY-KEY>`
(`commands/auto.md:324`) and exists **only in `$WORKTREE`** — the orchestrator passes
`$WORKTREE/docs/superpowers/plans/<STORY-KEY>.md`. The ticket did not cover this; getting it wrong
yields `ERROR=plan-not-found` on every `/auto` story.

**`refs/domain-agent-handoff.md`, new `## Plan slice` section** — the agent-side half of the guard:

## Script over subagent — the decision and its justification

**Decision: a script.** Same test NA-92 (G3, `docs-sync-gate.sh`) and NA-93 (H, `loop-decide.sh`)
applied, same answer:

| Criterion | Script | Subagent |
| --- | --- | --- |
| Determinism | heading regex + boundary rule; identical output for identical input | can mis-decide a phase boundary |
| Token cost | ~0 — executed, never read | dispatch + return, per phase, per round |
| Instruction surface | **+0** — never enters any context window | a new ref every reader pays for |
| Failure mode | non-zero exit, `ERROR=` key, machine-detectable | prose return, needs interpretation |

No step in this path requires judgement. The one place judgement *would* have been needed — "which
phases did the diff touch, for the reviewer?" (the ticket's second open item) — is removed from
scope entirely by shipping site C as path-not-paste. The question is answered by deleting it.

## Error Handling

| Scenario | Behaviour | Exit / effect |
| --- | --- | --- |
| Plan path absent | `ERROR=plan-not-found`, no `SLICE=` | exit 2 → orchestrator STOPs, consistent with `principal-engineer-playbook.md:96-97` |
| Unknown mode / wrong arg count | `ERROR=bad-mode` / `ERROR=bad-args` | exit 2 → STOP |
| Zero phase headings in the doc | `GRAMMAR=unmatched`, `SLICE=<plan path>` | exit 0 → agent reads the whole plan |
| Phase headings present, none for this agent | `GRAMMAR=matched`, `SLICE=<plan path>` | exit 0 → agent reads the whole plan |
| `tmp-dir.sh` unresolvable | falls back to bare `./.tmp` — already guaranteed non-empty by `scripts/tmp-dir.sh` (its `\|\| true` + comment block) | exit 0 |
| Slice file written but unreadable at dispatch time (tmp reaped mid-run) | orchestrator `TASKS>0` assert already passed → agent-side clause fires | `Status: blocked` → PE Step 5 STOP at `:434` |
| `TASKS=0` with a tmp-file `SLICE` | unreachable by construction | if observed → STOP, never dispatch |

**Workspace-integrity interaction — verified, not assumed.** Slice files land under
`$(tmp-dir.sh)` = `./.tmp/<session-key>` relative to CWD. `.tmp/` is gitignored (`.gitignore:61`),
and both integrity checks use `git status --porcelain` **without** `--ignored`
(`scripts/assert-workspace-clean.sh:51,86`; `principal-engineer-playbook.md:422`), so slices are
invisible to PE Step 5's primary-checkout assert and QA Step 3's worktree stray-file check. The
ticket asked for this to be verified before relying on it — it is verified here.

The orchestrator's CWD is the primary checkout for the whole run (`principal-engineer-playbook.md:240`
— "the primary checkout is NEVER switched to the story branch"; it reaches the worktree only via
`git -C "$WORKTREE"`), so slices land in the primary's `.tmp/` with no extra discipline. They
survive the Step-7 worktree teardown, which a worktree-local `.tmp/` would not. `cleanup-tmp.sh`
reaps the dir at `SessionEnd` (`plugins/sdlc/hooks/hooks.json:18`).
