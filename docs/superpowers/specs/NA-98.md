## Overview

Agent rule writes and QA review-round records stop landing as committed files on the story branch and are instead captured to a gitignored staging area that is indexed into the context-mode plugin for in-session recall. A memory file enters a PR only when a human promotes a captured item through `/sdlc:docs distill`.

## Data Model

This project has no database. "Entities" here are on-disk artifacts with YAML frontmatter — the same class the existing rule/review schemas define.

### New Entities

**Capture record — rule kind.** Path `.claude/memories/captured/rules/<STORY-KEY>--<rule-id>.md`.

| Field | Type | Nullable | Default | Notes |
| --- | --- | --- | --- | --- |
| id | string | No | — | kebab-case rule id; equals the `<rule-id>` filename segment |
| agent | string[] | No | — | exactly `[<capturing-agent>]` for own-domain; length >= 2 for cross-domain |
| trigger | string[] | No | — | 1-6 lowercase keyword phrases |
| rule | string | No | — | ONE line, <= 200 chars |
| evidence | string[] | No | — | length >= 1; Jira key \| `PR#n` \| 7-40 char SHA |
| uses | number | No | 0 | never incremented while captured — counters only move on promoted rules |
| status | `"captured"` | No | `captured` | capture-only status; never `active`, so `collect-memory.sh` cannot pick it up |
| captured | string | No | — | ISO-8601 UTC timestamp of the capture write |
| story | string | No | — | originating Jira key, e.g. `NA-98` |
| origin | `"domain-agent"` \| `"qa-round"` | No | — | which write path produced it |
| promote-target | string | No | — | repo-relative path this record becomes on promotion, e.g. `.claude/memories/agents/web-engineer/<rule-id>.md` |

**Capture record — review kind.** Path `.claude/memories/captured/reviews/<YYYY-MM-DD>-<STORY-KEY>[-rN].md`.

| Field | Type | Nullable | Default | Notes |
| --- | --- | --- | --- | --- |
| story | string | No | — | Jira key; must match the filename segment |
| date | string | No | — | `YYYY-MM-DD`; must match the filename segment |
| domains | string[] | No | — | agents this round touched; `[]` only when `issue_count` is 0 |
| root_causes | string[] | No | — | tokens from `${CLAUDE_PLUGIN_ROOT}/refs/root-cause-vocab.txt`; `[]` only when `issue_count` is 0 |
| issue_count | number | No | — | count of Critical + Important findings this round |
| captured | string | No | — | ISO-8601 UTC timestamp |
| origin | `"qa-round"` | No | `qa-round` | fixed for this kind |
| promote-target | string | No | — | `.claude/memories/reviews/<YYYY-MM-DD>-<STORY-KEY>[-rN].md` |

Body of a review capture is unchanged from today's round file: `## Issues` / `## Preventions` / `## Rules written` when `issue_count > 0`; frontmatter only when `issue_count: 0`.

**Staging-area ignore marker.** `.claude/memories/captured/.gitignore`, content exactly:

```gitignore
*
!.gitignore
```

Self-ignoring so the staging area is invisible to git in **every** consumer repo without editing that repo's root `.gitignore` — the plugin is public and must not depend on nightshift's root ignore file. This is the mechanism that satisfies AC3 and AC6.

Entity base class: N/A — no ORM in this project. The frontmatter base is the existing 7-field rule schema (`refs/domain-agent-handoff.md`) and the existing 5-field review schema (`refs/qa-engineer-playbook.md` Step 5); each is extended with the four capture-only fields above and nothing else, so a promotion is a field-strip plus a move, never a reshape.

## API Surface

No HTTP surface. The callable contracts are two shell scripts and one MCP tool call.

### New Endpoints

| Method | Path | Auth/Route Type | Description |
| --- | --- | --- | --- |
| exec | `plugins/sdlc/scripts/capture-learning.sh rule <agent-or-shared>/<rule-id> <STORY-KEY> <body-file>` | agent-local shell, no network | Write/overwrite one rule capture; prints `CAPTURED=<path>` |
| exec | `plugins/sdlc/scripts/capture-learning.sh review <STORY-KEY> <YYYY-MM-DD> <round> <body-file>` | agent-local shell, no network | Write/overwrite one review capture; prints `CAPTURED=<path>` |
| exec | `plugins/sdlc/scripts/list-captured.sh [--json] [--story <STORY-KEY>] [--kind rule\|review]` | agent-local shell, no network | Enumerate the capture corpus for distill |
| MCP | `ctx_index({ path, source })` | context-mode MCP, session-scoped | Index one capture file so `ctx_search` surfaces it in-session |

`ctx_index` is only callable where MCP tools exist. Every SDLC domain agent declares `tools: Read, Write, Edit, Bash, Skill` — **no MCP** — so a domain agent can never call it. The call therefore lives in the orchestrator layer (`/impl` Principal Engineer playbook, `/review` QA Engineer playbook), both of which run **inline in the top-level session** and do have MCP, plus `knowledge-engineer` once its `tools:` line is widened. This split is load-bearing, not incidental.

### Request / Response Shapes

```typescript
type CaptureKind = "rule" | "review";
type CaptureOrigin = "domain-agent" | "qa-round";

interface RuleCaptureFrontmatter {
  id: string;
  agent: string[];
  trigger: string[];
  rule: string;
  evidence: string[];
  uses: number;
  status: "captured";
  captured: string;
  story: string;
  origin: CaptureOrigin;
  "promote-target": string;
}

interface ReviewCaptureFrontmatter {
  story: string;
  date: string;
  domains: string[];
  root_causes: string[];
  issue_count: number;
  captured: string;
  origin: "qa-round";
  "promote-target": string;
}

interface CaptureListEntry {
  kind: CaptureKind;
  path: string;
  id: string;
  story: string;
  captured: string;
  promoteTarget: string;
  summary: string;
  agents: string[];
}

interface CaptureListOutput {
  entries: CaptureListEntry[];
  count: number;
}

type PromotionChoice = "memory" | "adr" | "skip";

interface PromotionDecision {
  path: string;
  choice: PromotionChoice;
  target: string | null;
}
```

`summary` = the `rule` line for a rule capture; `"<issue_count> findings — <root_causes joined>"` for a review capture. `agents` = `agent` for a rule capture, `domains` for a review capture. Default (no `--json`) output is one tab-separated line per entry in field order `kind, id, story, promoteTarget, summary` — cheap for an agent to read without a JSON parse.

### Permissions

Roles are the SDLC agents defined in `plugins/sdlc/agents/` plus the founder (the human at the confirmation gate). There is no user/role system in this project — this is the permission source.

| Role | Capture (write) | List | Index (`ctx_index`) | Promote to memory file | Promote to ADR | Delete capture |
| --- | --- | --- | --- | --- | --- | --- |
| domain engineers (web/platform/db/sync/mobile/ai-enablement) | ✓ own `agent` dir + `shared/` | ✓ | ✗ no MCP in `tools:` | ✗ | ✗ | ✗ |
| qa-engineer | ✓ rule captures for the fixing agent + review captures | ✓ | ✗ — playbook runs inline; the session indexes | ✗ | ✗ | ✗ |
| knowledge-engineer | ✗ | ✓ | ✓ at distill time, to search the corpus | ✓ founder-confirmed only | ✓ founder-confirmed only | ✓ only captures the founder confirmed as promoted/discarded |
| ai-enablement-engineer (maintenance op) | ✓ own dir | ✓ | ✗ | ✗ | ✗ | ✓ stale captures past the retention window, founder-confirmed |
| principal-engineer / orchestrators (inline, top-level session) | ✗ | ✓ | ✓ once per capture written this phase | ✗ | ✗ | ✗ |
| founder (human) | — | — | — | ✓ decides every promotion | ✓ decides every promotion | ✓ decides every deletion |

The capture write permission intentionally widens what QA may author (it already creates rule files under another agent's directory today, per `qa-engineer-playbook.md` Step 5) — because a capture is untracked and reversible, this stops being the sanctioned-exception it is today and becomes ordinary.

## Backend Implementation

**Owning agent:** `ai-enablement-engineer` (owns `plugins/`, `.claude/` per the project-context workspace→agent table). `platform-engineer` owns the single `.github/workflows/ci.yml` step.

**New scripts** (`plugins/sdlc/scripts/`):

| File | Responsibility |
| --- | --- |
| `capture-learning.sh` | Validate args, resolve `promote-target`, emit frontmatter + body, write atomically to the staging path, print `CAPTURED=<path>` |
| `list-captured.sh` | Walk `.claude/memories/captured/**`, parse frontmatter, emit TSV or `--json` |

Both must reuse the existing `extract_fm` / `parse_frontmatter` awk pair from `collect-memory.sh` rather than re-implementing a parser — extract it to a sourced helper if duplication would otherwise result. Both must run under bash 3.2 (no associative arrays), consistent with the rest of `plugins/sdlc/scripts/`.

**New test** (`plugins/sdlc/scripts/__tests__/capture-learning.test.sh`) covering: both kinds round-trip; `promote-target` correctness for own-dir vs `shared/`; idempotent overwrite; `collect-memory.sh` returns zero captured entries when the staging area is populated; `list-captured.sh` TSV and `--json` shapes; the staging `.gitignore` makes `git status --porcelain` empty after a capture.

**Instruction-surface edits:** the Modified Entities table above is the exact file list. Two contracts change shape and must be stated verbatim in the edited docs:

- Domain agent memory write → `bash ${CLAUDE_PLUGIN_ROOT}/scripts/capture-learning.sh rule <target> <STORY-KEY> <body-file>`; the admission test in `refs/domain-agent-handoff.md` is unchanged and still gates whether a capture is written at all.
- QA Step 5 → captures replace all three writes (round file, rule entries, counter-only updates), and the step's terminal `git add`/`commit`/`push` block is deleted. The `Learnings:` line of the Step-8 verdict becomes `captured to <N> file(s): <ids>`.

**Counter-only updates.** A `uses` increment on an already-committed rule is itself a committed diff, so it falls under AC1's prohibition. Replace it with a rule capture whose `id` matches the existing rule and whose `promote-target` is that existing rule's path — promotion then merges the counter. Rationale: keeps the "PR carries no unreviewed memory diff" invariant total rather than leaving one exception that still dirties every PR.

**context-mode indexing.** After the capture-producing phase completes, the orchestrator calls `ctx_index({ path: <capture path>, source: "sdlc-capture:<STORY-KEY>" })` once per capture file written this phase. Failure or tool-absence is logged in one line and never blocks — the file on disk is the durable record; the index is recall convenience only. Do not attempt indexing from a domain agent.

**Durability constraint (why the file is the record).** context-mode's content and session stores are SQLite databases at `join(tmpdir(), "<prefix>-<pid>.db")` — per-process and ephemeral (verified in `src/db-base.ts` `defaultDBPath` at 1.0.103). Anything only inside `ctx_index` dies with the session, so a later `/sdlc:docs distill` run could never read it. The gitignored staging file is therefore the source of truth and `ctx_index` is a same-session read accelerator.

**`/sdlc:docs distill` integration (AC4).** Phase 1 gains the capture corpus as an evidence source alongside the maintenance-op nomination list. For each capture the founder gate presents `kind`, `id`/`story`, `summary`, and `promote-target`, and takes one of three per-item choices: `memory` (write the capture to its `promote-target`, stripping `captured`/`story`/`origin`/`promote-target` and setting `status: active` for a rule), `adr` (feed it into the existing ADR draft cluster), or `skip` (leave it staged). Phase 2 writes only confirmed items and deletes only the captures it promoted. Distill's existing claude-mem tools-absent halt must be relaxed for this path: the capture corpus is repo-native, so distill runs on captures alone when claude-mem is unavailable.

## Permissions Detail

- `ai-enablement-engineer` may write every path in this spec **except** `.github/workflows/ci.yml` — that file is `platform-engineer`-owned per the project-context table, and the standing rule `ci-yml-outside-ai-enablement-write-scope-refuse` requires a refusal rather than a courtesy edit. The CI step is a separate platform-engineer task in the same story.
- `knowledge-engineer` gains read access to `.claude/memories/captured/**` and write access to it **only** to delete a founder-confirmed promoted capture. It still never writes `.claude/memories/agents/**` outside the promotion path the founder confirmed.
- No agent may promote without the founder gate. A promotion applied without an explicit confirmation is the same violation class as a silent memory write today.
- The staging area is untracked, so nothing in it is subject to the review gate — which is exactly why nothing in it may reach a committed path without the gate.

## Error Handling

| Scenario | Behaviour | Exit code |
| --- | --- | --- |
| `capture-learning.sh` called with an unknown kind | Print usage to stderr, write nothing | 1 |
| `capture-learning.sh` body file missing/unreadable | Print the path to stderr, write nothing | 1 |
| `capture-learning.sh` rule id is not kebab-case, or target agent dir is unknown | Print the offending value to stderr, write nothing | 1 |
| `.claude/memories/captured/` absent at capture time | Create it plus the `.gitignore` marker, then proceed | 0 |
| Capture path already exists | Overwrite (idempotent re-capture of the same rule id / same round) | 0 |
| `list-captured.sh` with an empty or absent staging area | Print nothing (TSV) or `{"entries":[],"count":0}` (`--json`) | 0 |
| `list-captured.sh` hits a capture with malformed frontmatter | Skip it, warn on stderr, continue with the rest | 0 |
| `ctx_index` unavailable or errors | Log one line, continue — never blocks the phase | n/a |
| `check-frontmatter.sh` finds a malformed capture | Warning only, never a failure — the staging area must not break CI | 0 |
| Distill finds zero captures and zero nominations | Clean no-op, no PR — matches today's "no promotable candidates" behaviour | 0 |
| Founder chooses `memory` but `promote-target` already exists | Merge counters and evidence into the existing file, never clobber the `rule` line; surface the merge at the gate | 0 |

## Out of Scope

- Building or modifying the context-mode plugin itself — this story consumes `ctx_index`/`ctx_search` as they exist at 1.0.103.
- Backfilling or migrating the ~250 rule files and 28 review files already committed under `.claude/memories/` — they stay exactly as they are (AC5).
- Redesigning the ADR pipeline's drafting, tagging, audience-preservation, or index-regeneration mechanics beyond adding the capture corpus as a source and the per-item promotion choice.
- Making `collect-memory.sh` read captures into an agent's read path — promotion stays the only route from a capture into agent behaviour.
- Any change to the 7-field rule schema or the 5-field review schema as committed today.
- Replacing claude-mem as distill's observation source; this story only removes claude-mem's ability to _block_ a capture-evidenced distill run.

## Open Questions

- [ ] Should `.claude/memories/captured/` sit inside `.claude/memories/` or under `.tmp/`? — Suggested default: **inside `.claude/memories/captured/`**. `.tmp/` is session-keyed and deleted by the `SessionEnd` hook, which would destroy captures before a later distill run; AC4 requires them to still be "found in the repo".
- [ ] Retention for unpromoted captures — Suggested default: reuse the existing `Review retention window` token (`6 months` here) and let the `ai-enablement-engineer` maintenance op's review-file GC sweep stale captures under the same founder gate. No new project-context token.
- [ ] Should worktrees share one capture area? — Suggested default: **yes** — capture to the primary checkout's `.claude/memories/captured/` resolved via `git rev-parse --path-format=absolute --git-common-dir`, so a QA fix round in a worktree and a later distill in the primary see the same corpus.
- [ ] Does the `Learnings:` line of the QA Step-8 verdict stay mandatory? — Suggested default: **yes**, reworded to `captured to <N> file(s): <ids>`; it is how the orchestrator learns which paths to `ctx_index`.
- [ ] Does `/sdlc:analyze`'s `story-merged-without-review-entry` finding become permanently noisy once round files stop being committed? — Suggested default: extend the finding to accept a captured round file as satisfying evidence, and only report when neither a committed nor a captured round file exists for the merged key.
