## Overview

Introduce `plugins/sdlc/scripts/memory-root.sh`, a shared resolver that returns one absolute memory root per repository outside the git working tree, and repoint the five scripts that currently hardcode `.claude/memories` to source it. Only the directory prefix moves — the on-disk layout, the 7-field rule schema, `SDLC_CAPTURE_ROOT`, the `agents/shared/` audience rules, and the ADR read path are unchanged.

## Data Model

The "data model" here is an on-disk directory contract, not a database. There is no ORM, no entity base class, and no migration — see Out of Scope for the corpus move (NA-102).

### New entities

`plugins/sdlc/scripts/memory-root.sh` — new shared resolver, dual-mode (sourceable library + executable CLI).

| Field | Type | Nullable | Default | Notes |

## API Surface

The "API" is the script CLI + sourced-function surface. No HTTP endpoints exist in this story.

### New endpoints

| Method | Path | Auth/Route type | Description |
| --- | --- | --- | --- |
| CLI | `memory-root.sh --print-root` | Local shell, no auth | Print the absolute resolved root, no trailing slash. Creates nothing |
| CLI | `memory-root.sh --print-key` | Local shell, no auth | Print `<repo-key>` only |
| CLI | `memory-root.sh --ensure` | Local shell, no auth | Print the root **and** create the layout below it, idempotently |
| Sourced fn | `sdlc_memory_root [<start-dir>]` | In-process, no auth | stdout = absolute root; `return 1` + stderr on failure; never `exit` |
| Sourced fn | `sdlc_repo_key [<start-dir>]` | In-process, no auth | stdout = `<repo-key>`; `return 1` + stderr on failure; never `exit` |
| Sourced fn | `sdlc_primary_worktree [<start-dir>]` | In-process, no auth | stdout = the primary worktree's absolute path (the `primary` the key derivation already computes); `return 1` + stderr on failure; never `exit`. Exists so a consumer needing the primary checkout — `list-captured.sh`'s legacy fallback — does not re-implement the porcelain probe |
| Sourced fn | `sdlc_memory_ensure <root>` | In-process, no auth | Creates the layout; `return 1` + stderr on failure; never `exit` |

`<start-dir>` defaults to `$PWD` and is used only for git probing.

### Resolution contracts

Root precedence — first match wins, evaluated top to bottom:

```text
SDLC_MEMORY_ROOT non-empty -> use verbatim, strip trailing "/"   # no git probing; the escape hatch for CI and tests
otherwise                  -> "${XDG_DATA_HOME:-$HOME/.local/share}/sdlc/memories/$(sdlc_repo_key)"
```

`<repo-key>` derivation — first match wins:

```text
primary := first "worktree " line of `git worktree list --porcelain`   # already symlink-resolved by git; identical from a linked worktree
remote  := `git -C "$primary" remote get-url origin` , else `git -C "$primary" remote | head -1` -> get-url
remote non-empty -> slug(remote)
remote empty     -> "$(slug "$(basename "$primary")")-$(hash8 "$primary")"
key longer than 100 chars -> truncate the leading slug, ALWAYS keep the trailing "-<hash8>" when present
normalise (ALWAYS the last step) -> squeeze runs of "-" to one, strip leading and trailing "-"
slug component now empty  -> key := "repo-<hash8>"   # e.g. an all-punctuation or all-CJK basename, or a slug consumed by truncation
```

Normalisation is total: the derived key always satisfies `^[a-z0-9][a-z0-9-]*$` and is never empty, so there is no key-validation failure path to specify.

`slug()` — applied in this exact order, so an SSH and an HTTPS remote for the same repo produce the same key:

```text
lowercase
strip leading scheme         "^[a-z0-9+.-]*://"
strip leading userinfo       "^[^@/]*@"
strip trailing "/"
strip trailing ".git"
replace every char outside [a-z0-9] with "-"
squeeze runs of "-" to one
strip leading and trailing "-"
```

Worked example (this repo, both remote forms):

```text
git@github.com:whimzyLive/nightshift-ai.git       -> github-com-whimzylive-nightshift-ai
https://github.com/whimzyLive/nightshift-ai.git   -> github-com-whimzylive-nightshift-ai
```

`hash8()` — first 8 lowercase hex chars, using the first available command:

```text
shasum -a 256      # macOS default and most Linux
sha256sum          # GNU coreutils
cksum              # POSIX last resort: printf '%08x' <first field>, then cut -c1-8
```

Input to `hash8` is the primary worktree's absolute path with **no trailing newline** (`printf '%s'`, never `echo`).

## Backend Implementation

**New file:** `plugins/sdlc/scripts/memory-root.sh`, mode `755`, `#!/usr/bin/env bash`. Shell options are set **only inside the executed-directly guard** (`if [ "${BASH_SOURCE[0]}" = "$0" ]; then set -uo pipefail; fi`) — never at file scope, so sourcing cannot turn `pipefail`/`nounset` on in a caller.

Sourcing safety — all five consumers already set `set -uo pipefail` themselves and three (`check-frontmatter.sh`, `collect-memory.sh`, `list-captured.sh`) also set `nullglob`; sourcing must leave every one of those states exactly as it found them:

| Constraint | Statement |
| --- | --- |
| No side effects on source | Defines functions only; never `mkdir`, never writes, never `exit` |
| No shell-option mutation on source | `set`/`shopt` appear only inside the executed-directly guard, never at file scope — every consumer keeps whatever `pipefail`/`nounset`/`nullglob` state it had. This is a forward-compatibility invariant, not a fix for a live defect: all five set `pipefail` on line 2 (`capture-learning.sh` line 10) today, so nothing regresses now, but a consumer that later drops it must not have it silently re-enabled by the source |
| `set -u` safe | Every env read is `${VAR:-}` — the functions are written to be correct with `set -u` both on and off |
| Namespaced | Every function is prefixed `sdlc_`; defines no `die`, `here`, or other caller-colliding name |
| Executed-vs-sourced | CLI arg handling runs only when executed directly (`[ "${BASH_SOURCE[0]}" = "$0" ]`) |
| Bash 3.2 | No associative arrays, no `local -n`, no `${var^^}`, no `mapfile` |
| Portability-lint clean | Uses `${HOME}` / `${XDG_DATA_HOME}` only — never a literal `/Users/...` or `/home/...`, which `tools/portability-lint.sh` check #1 rejects inside `plugins/**` |

**`sdlc_memory_ensure <root>` creates exactly:** `<root>/agents/shared/`, `<root>/reviews/`, `<root>/captured/rules/`, `<root>/captured/reviews/`, and `<root>/captured/.gitignore` containing `*\n!.gitignore\n`. It creates no per-agent directory — `collect-memory.sh` already guards every rule directory read with `[ -d … ]`.

**`capture-learning.sh`:** `ensure_capture_root()` and its error strings stay exactly as they are — `--print-root` must keep ensuring the layout (the existing T2a/T2b/T2c assertions depend on it).

**`list-captured.sh` — dual-root read, transition shim:** the `SDLC_CAPTURE_ROOT` branch stays first and unmodified. Otherwise it lists `<resolved-root>/captured` **and** `<primary-worktree>/.claude/memories/captured` — the primary from `sdlc_primary_worktree`, **not** `git rev-parse --show-toplevel` — each included only if it exists, deduped by `<kind>/<basename>` with the resolved root winning. The primary is load-bearing: `capture-learning.sh:30` writes into `$main` today (asserted by `capture-learning.test.sh` T2e/T2e2/T2e3b), so from a linked worktree — the plugin's normal mode — git-toplevel would list the linked worktree's `.claude/memories/captured/`, which holds only the tracked `.gitignore` marker, and every staged capture would stay invisible. Without this fallback, every capture already staged in `.claude/memories/captured/` — the nomination input for `refs/adr-pipeline.md` and `refs/qa-engineer-playbook.md` — goes invisible the moment this story merges; those files are untracked and gitignored, so NA-102 would have nothing in git to migrate them with and a routine `git clean -fdx` would destroy them. Resolver failure keeps the existing hard-error path when no legacy root exists; when the legacy root exists it is a WARNING on stderr plus a legacy-only listing. `collect-memory.sh` and `check-frontmatter.sh` below correctly use git-toplevel instead — their legacy corpus is tracked, so it is present in every worktree.

**`collect-memory.sh` — dual-root read, transition shim:**

```text
arg2 (<repo-root>) present -> LEGACY-ONLY mode: roots := [ "$2/.claude/memories" ]   # keeps memory-frontmatter.test.sh fixtures hermetic
arg2 absent                -> DUAL mode: roots := [ <resolved-root> , <git-toplevel>/.claude/memories ]  , each included only if it exists
resolver fails in DUAL mode -> one-line WARNING on stderr, continue with the legacy root alone, still exit 0   # a dispatch must never die on memory collection
emit each RULE id at most once, first root wins   # resolved root precedes legacy
LEGACY v1 flat-diary banner: probed under each root in order, printed at most once
adr_dir := (arg2 // git-toplevel // pwd)/docs/adr   # UNCHANGED
```

Why the legacy fallback exists: NA-101 lands before NA-102 migrates the 273 tracked corpus files. Without it, every domain agent silently loses its whole rule corpus the moment this story merges. The fallback is a no-op once NA-102 empties the in-repo tree.

**Shim removal — committed, not an open question.** NA-102 removes the legacy in-repo fallback from `collect-memory.sh`, `check-frontmatter.sh` and `list-captured.sh` in the same PR that empties `.claude/memories/`, leaving exactly one code path, and adds a test asserting no script under `plugins/sdlc/scripts/**` still references `.claude/memories`. That test also trips on two non-shim sites NA-101 deliberately leaves alone, so NA-102 must sweep them in the same PR (or scope the test to non-comment path references): `collect-memory.sh`'s v1 flat-diary WARNING string, and the two comment lines in `__tests__/no-hardcoded-project-key.test.sh`. NA-102 also inherits one precedence rule: when a rule id exists in **both** roots at migration time, the resolved-root copy wins — during the shim "first root wins" hides the stale tracked legacy copy, so moving it in blindly would clobber a newer promoted rule. These are preconditions NA-102 inherits from NA-101, not decisions left open.

**`check-frontmatter.sh` — dual-root validation, keeps the CI gate alive:**

```text
arg1 (<repo-root>) present -> LEGACY-ONLY mode: mem_roots := [ "$1/.claude/memories" ]   # fixture runs stay hermetic and byte-identical
arg1 absent                -> DUAL mode: mem_roots := [ <resolved-root> , <git-toplevel>/.claude/memories ] , each included only if it exists
resolver fails in DUAL mode -> stderr "check-frontmatter: RESOLVER-FAILED — <reason>", validate the legacy root anyway, then exit 1 whatever the findings   # distinct from "root absent"; a resolver regression must never read as a green gate
per root -> print "check-frontmatter: <n> file(s) validated under <root>"   # a zero-file run is visible in the CI log
neither root exists -> print "check-frontmatter: OK — no memory root present (0 files validated)" , exit 0
offenders and warnings: union across roots
duplicate-id detection: scoped PER ROOT, never across roots   # the same id in both roots mid-migration is expected, not a defect
ADR line-1 frontmatter scan: "$repo_root/docs/adr" — UNCHANGED
```

Declared output-contract change: the absent-root line replaces today's `check-frontmatter: OK — $mem_root not present` (`check-frontmatter.sh:120`), which no longer names a single root. Nothing asserts the old string (`__tests__/`, `tools/` and `.github/` are clean), so no test changes with it — it is called out only because it is a visible output contract.

**`assert-workspace-clean.sh`:** `capture_root_rel()` keeps its `SDLC_CAPTURE_ROOT` branch verbatim; the else-branch becomes `$(sdlc_memory_root)/captured`. The existing "not under the primary checkout → return empty → passthrough filter" branch already covers the new default correctly, so a default-configured capture write can no longer appear in `git status --porcelain` at all. `snapshot`/`assert` stdout contracts (`PRIMARY_HEAD`, `PRIMARY_STATE_FILE`, `PRIMARY_PRE_DIRTY`, `WORKSPACE_INTEGRITY`, `WORKSPACE_VIOLATION`) are unchanged. ## Error Handling

| Scenario | Behaviour | Exit |
| --- | --- | --- |
| `SDLC_MEMORY_ROOT` set but relative | stderr `memory-root.sh: SDLC_MEMORY_ROOT must be an absolute path`, nothing created | 1 |
| `XDG_DATA_HOME` set but relative | **Not an error** — ignored and treated as unset per the XDG Base Directory spec, so the root falls back to `$HOME/.local/share/sdlc/memories/<repo-key>`; nothing is created under `$PWD`. Deliberately unlike `SDLC_MEMORY_ROOT`, which hard-fails | 0 |
| `HOME` and `XDG_DATA_HOME` both unset, `SDLC_MEMORY_ROOT` unset | stderr names both variables | 1 |
| `git worktree list --porcelain` fails (not a repo) | stderr `memory-root.sh: 'git worktree list --porcelain' failed — cannot resolve the memory root` | 1 |
| Repository is bare | stderr `memory-root.sh: main repository is bare — no primary checkout` | 1 |
| No `worktree ` entry in porcelain output | stderr names the missing entry | 1 |
| No `shasum`/`sha256sum`/`cksum` available | stderr names the missing hash tool | 1 |
| Resolver fails inside `capture-learning.sh` | Existing `die` path — abort, `wrote nothing` wording preserved | 1 |
| Resolver fails inside `list-captured.sh` | Legacy root exists → WARNING on stderr, list the legacy root alone; no legacy root → existing hard-error path, stderr, no output | 0 with legacy / 1 without |
| Resolver fails inside `collect-memory.sh` | WARNING on stderr, fall back to legacy in-repo root, dispatch continues | 0 |
| Resolver fails inside `check-frontmatter.sh` | `RESOLVER-FAILED` on stderr, validate the legacy root anyway, then fail — an absent `~/.local/share` is **not** a resolver failure and still exits 0 | 1 |
| Resolver fails inside `assert-workspace-clean.sh` | Treat `rel` as empty (passthrough filter); never fabricate a verdict | unchanged |
| `--ensure` cannot create the root (permissions, path segment is a file) | stderr names the path, creates nothing partially | 1 |
| Two clones of the same remote on one machine | **Intended** — they share one root and one staging area. Set `SDLC_MEMORY_ROOT` per clone to separate them |
| `SDLC_MEMORY_ROOT` exported globally (shell profile) | Every repo on the machine collapses into one root and one staging area, and all git probing is silently skipped — strictly worse than the collision above and invisible. Scope it per clone (direnv, a wrapper script), never in a shell profile |
| Resolved root absent on first use | Not an error — readers treat "absent" as "empty"; `capture-learning.sh` creates it on first write |

Validation rules: `SDLC_MEMORY_ROOT` must be absolute; a relative `XDG_DATA_HOME` is invalid and is ignored — treated as unset, falling back to `$HOME/.local/share` — per the XDG Base Directory spec, never a hard error; `<repo-key>` must match `^[a-z0-9][a-z0-9-]*$` and must be non-empty, which the final normalisation step of the derivation guarantees unconditionally; `promote-target` must be root-relative and must start `agents/` or `reviews/`.
