# Bound domain-agent reads with offset/limit — Technical Spec

**Story:** NA-90 (workstream **E** of Epic NA-76 — SDLC token and cost optimisation programme)
**Feature:** docs/features/2026-07-30-sdlc-token-cost-optimisation-programme.md
**Date:** 2026-07-31

Artifact encoding contract: unpadded tables, no section dropped, one-line N/A, verbatim contracts, rationale as annotation, prose < 10 lines between headings. plugins/sdlc/refs/artifact-encoding.md

## Overview

Add a `## Bounded reads` clause to the domain-agent prompt contract that mandates locating content with `Grep`/`Glob` before loading it, and reading with `offset`/`limit` for files above a defined size threshold. Ships the measurement instrument and the CI presence guard alongside it, and defers the cut-rate claim to a named pilot occasion — E's 4.9% is an estimate until that pilot passes every gate (AC-5).

## Scope map — where C (NA-88) ends and E (NA-90) begins

NA-88 and NA-90 both edit the domain-agent read behaviour and both use the words `offset`/`limit`. They govern **disjoint** events. State the split before any other design decision:

| Question the clause answers | Owner | Where it lives |
| --- | --- | --- |
| May I read this path *again*? | **C — NA-88** | `## Context reuse`, `refs/domain-agent-handoff.md` |
| Given I am reading it again, how much do I read? | **C — NA-88** | `## Context reuse` line: `earlier read was windowed AND another region is needed -> read ONLY the missing region with offset/limit` |
| I have never read this path. Do I need to open it at all? | **E — NA-90** | `## Bounded reads` (new section) |
| I have never read this path and I do need it. How much of it do I read? | **E — NA-90** | `## Bounded reads` (new section) |

C's rules are all conditioned on a prior read existing in the transcript. Every C line presupposes `path already read` / `earlier read was windowed` / `Edit/Write returned success`. **C is silent on the extent of a first read** — its own spec says so verbatim: "C1's widening rule only governs a *second* read of an already-read path; it never mandates how a first read is sized" (`docs/superpowers/specs/NA-88.md`, Out of Scope). E supplies exactly that missing rule and nothing else.

### Measured baseline (all 115 top-level + 552 subagent transcripts of this project, 2026-07-31)

The Epic's E sizing is **verified and reproduces**. It is not a measurement artifact of the NA-89 kind:

| Figure | Epic NA-76 (2026-07-28) | Re-measured here (2026-07-31) | Verdict |
| --- | --- | --- | --- |
| Top decile share of Read tokens | 51% | 51.6% (domain agents) | reproduces |
| Read p95 | 12,201 | 9,924 | lower — NA-86/NA-87 shrank the plugin files being read |
| Read max | 24,966 | 25,188 | reproduces |
| Domain-agent share of all Read volume | not stated | 88.0% (10.98M of 12.48M est tok) | E's mechanism is correctly targeted |
| Windowed share of domain-agent reads | not stated | **26.1%** (1,380 of 5,292) | the baseline this story must move |

**Why this number is trustworthy where D's "3.1% rtk adoption" was not.** NA-89 F1 established that a transcript-derived counter cannot observe an rtk rewrite, because the harness records the model-authored `tool_use.input.command` and never the hook's `updatedInput`. That failure mode does **not** apply to `Read`: no hook rewrites `Read`'s input, `offset`/`limit` are recorded verbatim as authored, and the `tool_result` payload — the bytes actually billed — is recorded too. Result-to-call matching was **203/203 (100%)** on the first probe corpus. The instrument observes exactly what it claims to observe.

**One corpus trap, found the hard way, now a binding instrument rule.** Domain-agent reads are **not** in the top-level `*.jsonl` files and carry **no `isSidechain` flag** on this harness — `isSidechain` is `0` across all 69,092 records. Subagent transcripts live at `~/.claude/projects/<project>/<session-uuid>/subagents/agent-<id>.jsonl`. A non-recursive `~/.claude/projects/*/*.jsonl` glob silently drops **88% of read volume** and produces a confident, wrong conclusion (it did, on the first pass of this analysis: it showed domain agents contributing 0% and the top decile dominated by orchestrator playbook reads). Any instrument or measurement in this story **MUST** glob `*/subagents/*.jsonl` explicitly and print both partition counts.

### Addressable share — stated honestly, not inflated

Domain agents read four categories. E cannot bound all of them, because some are read whole *by design*:

| Category | Domain-agent read volume | Windowed today | E's claim on it |
| --- | --- | --- | --- |
| plugin-instruction | 3,765,538 tok (34.3%) | 733 / 1,723 | **carve-out** — a playbook/ref is executed, not searched; splitting it is workstream A |
| self-generated-artifact | 3,485,371 tok (31.7%) | 272 / 730 | **partial** — plan-doc slicing is NA-81 (parked); E bounds only ad-hoc reads of specs/plans it was not handed |
| source-other | 2,308,424 tok (21.0%) | 214 / 1,372 | **primary target** — real source files, located by symbol |
| project-config | 1,423,364 tok (13.0%) | 161 / 1,467 | **partial** — small files mostly under threshold |

E's honest addressable slice is therefore **~21% primary + a partial claim on ~45%**, not the full 51.6% top-decile figure. The Epic's 4.9% cut-rate is an estimate over the whole distribution; this spec does not adopt it as a target and AC-5 forbids counting it until the pilot passes.

### Threshold sizing — why 2,000 est tokens

`limit` is only worth mandating where the volume actually sits. Whole-file domain-agent reads at or above each candidate threshold:

| Threshold (est tok) | Whole reads >= T | Their volume | % of all domain-agent read volume |
| --- | --- | --- | --- |
| 1,000 | 1,974 | 8,194,608 | 74.6% |
| 1,500 | 1,432 | 7,522,903 | 68.5% |
| 2,000 | 1,139 | 7,019,073 | 63.9% |
| 3,000 | 798 | 6,229,627 | 56.7% |
| 5,000 | 486 | 5,017,561 | 45.7% |
| 8,000 | 293 | 3,822,431 | 34.8% |

**2,000 est tok** is the chosen threshold — it captures 63.9% of volume across 1,139 reads while leaving small files (the long tail where a windowed read costs an extra call and saves nothing) alone. Because an agent cannot measure est tokens before reading, the clause states the threshold in the unit the agent can actually act on: **400 lines**, the `limit` value, with `2,000 est tok ≈ 7,400 bytes ≈ ~400 lines` recorded as the derivation. Read's own default cap is 2,000 lines, so a bare `Read` is already bounded at 5× the threshold — the clause tightens an existing bound, it does not invent one.

### Phase 1 — `tools/` (platform-engineer)

**Create `tools/sdlc-analyser/read-bounding.py`** — Python 3, stdlib only, read-only, never writes to the repo or `~/.claude/`. Mirrors `duplicate-reads.py`'s conventions exactly (`STORY_KEY_RE`/`story_key()` for `--per-story`, `classify_category()` with the same four first-match-wins rules and `CATEGORY_ORDER`, `estTokens = floor(chars / 3.7)`, fail-loud on an unresolvable corpus, skip-and-count on an unparseable line then exit 0).

**The read-sizing rule, stated verbatim** — an unstated rule makes before/after non-reproducible, the same discipline `duplicate-reads.py`, `instruction-inventory.sh --padding` and `branch-inventory.sh` already follow:

```text
a Read call := an item of record["message"]["content"] with type == "tool_use" and name == "Read"
its result  := the item with type == "tool_result" and tool_use_id == that call's id
estTokens   := floor(len(result text) / 3.7)          # the bytes actually billed, not a file-size estimate
lines       := result text newline count + 1          # drives the windowed-cost model in Decision 2
windowed    := input.offset is not None OR input.limit is not None
whole       := NOT windowed
a call with no matched result -> excluded from every volume figure, counted in unmatchedCalls
```

**The corpus rule, stated verbatim** (this is the trap named in the baseline section — the tool enforces it so no caller can repeat it):

```text
origin := subagent   IF the transcript path contains "/subagents/"
origin := orchestrator OTHERWISE
# isSidechain is NOT usable on this harness: 0 of 69,092 records carry it. Do not partition on it.
ASSERT corpus.subagentTranscripts > 0 ELSE print a loud one-line WARNING naming the
       */subagents/*.jsonl glob and that ~88% of read volume is likely missing
       # a warning, never exit 1 — a deliberately orchestrator-only run is legitimate
```

`--threshold N` overrides `thresholdEstTokens` (default `2000`) and drives `wholeReadsOverThreshold` only. `--per-story` groups by story key parsed from `gitBranch`, identically to `duplicate-reads.py`. `--json` emits `ReadBoundingReport`; without it, a human-readable table carrying the same numbers.

### Phase 2 — `plugins/sdlc/` (ai-enablement-engineer)

**Add `## Bounded reads` to `plugins/sdlc/refs/domain-agent-handoff.md`,** immediately after `## Context reuse` and before `## Memory write`. Lean pseudocode per ADR 0017 + `refs/pseudocode-notation.md`, in a plain or ` ```text ` fence — never ` ```bash `. The section's required content, as a contract on the implementer (exact wording is the implementer's, the decisions are not):

```text
you need a named symbol/string, not the whole file -> Grep/Glob for it FIRST, then Read with offset around the hit
file is over the threshold AND you are not executing it as instructions -> Read with limit; widen only if the window proves insufficient
threshold := ~400 lines (limit=400)   # 2,000 est tok ~= 7,400 bytes ~= 400 lines; Read's own default cap is 2,000 lines
```

Carve-outs — a whole-file read here is correct, not a violation:

```text
the file IS the instruction you must execute (a playbook, a ref, your dispatch's plan/spec section) -> read whole   # executed end-to-end, not searched
the file is under the threshold -> read whole   # a second call would cost more than the bytes it saves
you are about to Edit it and must establish its current content -> read whole
```

Precedence, stated in the section so a later edit cannot erode it: **correctness wins.** A missing-context failure costs a QA round; an unnecessary whole read costs bytes. When in doubt, read more. This mirrors `## Context reuse`'s existing precedence line deliberately — the two sections must not disagree about which way to resolve a tie.

## Validation gates — and what each one cannot prove

Three standing rules from the merged siblings bind this design: a self-generated artifact is a smoke test (NA-88 D11); an artifact that cannot exercise the contract is not evidence about it; and static cost is declared as a positive number.

### Gate 1 — mechanical, pre-merge, CI. **Self-confirming — smoke test only.**

`bounded-reads.test.sh` passes (5 assertions) and the static instruction delta is declared. This story authors both the clause and the test that checks it, so a pass proves only that the author wrote what the author intended.

**What it cannot detect:** whether any agent actually obeys the clause. It is a presence check on text, nothing more. It is capable of failing — delete the section, drop a pointer, exceed the byte cap, or fold E into C, and it fails — so it is a real check on its own narrow subject, but its subject is not agent behaviour.

### Gate 2 — falsifiability of the instrument, pre-merge.

`read-bounding.py` must return **two materially different answers** over two corpora, or it is evidence about nothing:

| Corpus | Expected `windowedShare` | Purpose |
| --- | --- | --- |
| pre-NA-90 subagent transcripts (pinned file list) | ~26.1% | the measured baseline |
| a synthetic fixture corpus with every read windowed | 100% | proves the metric can reach the other end |
| a synthetic fixture corpus with every read whole | 0% | proves the metric can fail |

Both synthetic corpora ship as fixtures under `tools/sdlc-analyser/__tests__/fixtures/read-bounding/`. A tool that returned the same number against all three would be incapable of measuring anything. **Pin the real corpus to an explicit file list**, never `--count N` over most-recently-modified files — that window slides between runs, so the two sides of a delta would not be replaying the same bytes (`rtk-coverage.py`'s `--corpus-list` precedent).

### Gate 3 — independent runtime evidence, deferred to a named occasion. **The only gate that is evidence about the contract.**

**NA-90's own implementation run cannot be the pilot.** Its domain dispatches execute on the *pre*-change contract — the clause only exists once phase 2 commits, after every dispatch that could have honoured it. Quoting an after-number from this run would measure the old contract and read as if it measured the new one. This is NA-88's deferred-runtime reasoning applied unchanged.

**Pilot selection rule** (AC-2, AC-3, AC-4). The pilot is the first story after this PR merges that satisfies **all** of:

```text
ASSERT it dispatches >= 1 domain agent          # otherwise no subagent transcript exists to measure
ASSERT it is not NA-91, NA-92 or NA-93          # each changes read/context behaviour and would confound the delta
ASSERT it is a normal feature/defect story      # not a spec-only or plan-only run
```

Suggested default if no such story is queued: run `/sdlc:auto` on **NA-81** (plan-slicing, currently parked) — it dispatches domain agents and its own change is orthogonal to read *extent*. Confounder to record if used: NA-81 alters plan-doc read *volume*, so report `source-other` separately from `self-generated-artifact`.

The pilot's before/after block is recorded in the merged PR body (AC-4) and posted as a comment on **NA-90** (mirroring NA-88's tier-2 discipline), so the obligation cannot be silently dropped.

### Decision 1 — requests may rise if tokens fall significantly. **Founder decision, spec review gate, 2026-07-31.**

Grep-first **adds a call**: one `Grep` plus one windowed `Read` replaces one whole `Read`. The Epic's guardrail says requests per story *must not increase*, so E is in direct tension with it by construction.

> **Founder ruling, verbatim:** _"More requests are okay as long as the total token count decreases significantly."_

This is **direct authority**, not an inference from the Epic's tie-breaker. It **relaxes the Epic's "requests per story must not increase" guardrail for workstream E specifically** — and for E only; no other workstream inherits the relaxation. Every other Epic guardrail (cache hit rate >= 94%, QA rounds, blocked rate, review findings, loop passes) applies to E unchanged.

The ruling turns on the word _significantly_, which Decision 2 pins to a number. **The request-count delta is still measured and still reported** in every measurement block — the founder accepted more requests, which is not licence to stop counting them.

### Decision 2 — "significantly" is **>= 9,020 est tok/story**, derived from the top decile

An unquantified "tokens must drop significantly" passes on any reduction at all. That is the same unfalsifiable shape this Epic has already shipped twice — NA-87's tier-1 gate that could not fail, and the 3.1% rtk figure NA-89 falsified. E does not ship a third.

**Derivation.** Modelled over the 681 addressable reads (whole, >= 2,000 est tok, excluding the `plugin-instruction` carve-out) across the 52 story-labelled subagent transcripts. Model: each addressable read becomes one `Grep` (~100 est tok) plus one `Read` capped at the 400-line window, with the post-change size computed per read from that read's own recorded result as `estTokens * min(400, lines) / lines`:

| Slice of addressable reads | Reads | Modelled saving | Share of attainable | Per story |
| --- | --- | --- | --- | --- |
| top 10% | 68 | 469,040 | 51.6% | **9,020** |
| top 25% | 170 | 852,126 | 93.7% | 16,387 |
| top 50% | 340 | 923,440 | 101.6% | 17,758 |
| all 100% | 681 | 909,144 | 100.0% | 17,484 |

**The threshold is the top-decile line: 9,020 est tok/story.** Chosen because the top decile of addressable reads carries **51.6%** of the attainable saving — numerically the same 51.6% concentration the Epic's top-decile finding names and this spec's baseline independently reproduces. E exists to capture that decile; a change that fails to capture even it did not work, whatever else it moved.

Note the non-monotonicity: top-50% saves _more_ (101.6%) than all-100%, because the bottom half is a net **loss** — 468 of 681 addressable reads (68.7%) are files at or under 400 lines, where the window returns the whole file anyway and the `Grep` is pure overhead. This is why the under-threshold carve-out is load-bearing, not a nicety.

**The gate, falsifiable in both directions:**

```text
net domain-agent read volume falls by >= 9,020 est tok/story  -> PASS
net fall is > 0 but < 9,020 est tok/story                     -> FAIL -> REVERT
net volume flat or up                                         -> FAIL -> REVERT
any of QA rounds / blocked rate / review findings rose         -> FAIL -> REVERT   # Epic tie-breaker, NOT relaxed
request-count delta                                            -> REPORTED, never a pass/fail input (Decision 1)
```

**Which side the discriminating cases land on**, computed with the same model:

| Case | Post-change cost | Net | Verdict |
| --- | --- | --- | --- |
| 25,188 est tok read over ~1,500 lines (the corpus max) | Grep 100 + 6,717 window = 6,817 | **+18,371 saved** | one such read clears the whole threshold twice over |
| 2,100 est tok read over ~150 lines | Grep 100 + 2,100 whole = 2,200 | **-100 (a loss)** | below the line — the file is under the window cap, so the Grep buys nothing |

**Failure mode is revert, not argument.** If net tokens fall but by less than 9,020 est tok/story while request count rises, the change is **reverted** — not defended, not re-litigated, not shipped with a narrative. This mirrors NA-87's standing rule that a change which cuts tokens but raises QA rounds cost more than it saved. The one permitted alternative to reverting is narrowing the contract under AC-2 (raise the threshold, or move a category to the carve-out list) and **re-piloting** — never re-scoring the same pilot against a softer number.

### Static instruction cost — declared as a positive number

E's saving is runtime-only; its cost is static and paid on **every domain-agent dispatch**, because `domain-agent-handoff.md` is read whole per dispatch.

| Component | Est tokens | Note |
| --- | --- | --- |
| `## Bounded reads` section | +325 | mechanically capped at 1,200 bytes by assertion (c) |
| PE playbook item 14 | +35 | one line |
| QA playbook item 11 | +35 | one line |
| **Total static** | **+395** | budget: **<= 500 est tok**, declared, not netted out |

Per-story arithmetic, for honesty about the margin: ~+395 tok × ~4 domain dispatches ≈ **+1,580 tok/story cost**, against a modelled attainable saving of 17,484 est tok/story (Decision 2) and a gate threshold of 9,020. The static cost is ~18% of the gate threshold — real, and small enough that clearing the gate is still a genuine net win. It does **not** pay for itself if agents ignore the clause — which is precisely why Gate 1 is not the gate.

Headroom note: NA-88 consumed +993 against its own ≤1,000 budget, and the programme's AC-2 endpoint is ≤230,000 tok instruction load per story. E's +395 is a separate, smaller budget and is the last clause-shaped addition this ref can absorb before the section-splitting logic of workstream A has to be applied to `domain-agent-handoff.md` itself.

## Finding for the parent — not actioned by this story

`tools/sdlc-analyser/duplicate-reads.py` partitions classification state on `(transcript path, bool(record["isSidechain"]))` per NA-88's D9. **`isSidechain` is `0` on all 115 transcripts / 69,092 records of this project**, and subagent records live in separate `*/subagents/*.jsonl` files rather than inline in the parent transcript. The partition therefore degenerates to per-file, which is very likely the correct behaviour by accident — but D9's stated reasoning ("a subagent's records can share the same `.jsonl` file") does not describe this harness. If any `duplicate-reads.py` run was invoked with a non-recursive `~/.claude/projects/*/*.jsonl` glob it measured a small fraction of read volume while appearing complete. **Not changed here** — NA-88's instrument is explicitly out of scope. Raised for a decision on whether NA-88's measurement needs re-running with the corrected corpus.

> **Coordinator confirmation, 2026-07-31.** Verified independently and worse than stated above: the recorded NA-88 baseline covers **798 of 6,793 reads (11.7%)** — the non-recursive glob resolved 107 top-level files while 1,438 nested `subagents/agent-*.jsonl` files holding 5,995 reads were excluded. `isSidechain` was `false` in all 15,827 records sampled, so D9's partition is inert. The correction is posted on NA-88; no further action from this story.
