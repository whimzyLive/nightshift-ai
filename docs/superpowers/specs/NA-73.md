# Memory v2 — frontmatter-triggered rule memory + injection standard — Technical Spec

**Story:** NA-73 — Memory v2: frontmatter-triggered rule memory + injection standard (plugin protocol)
**Epic:** none (standalone story; blocks NA-74)
**Feature:** none — no `docs/features/*.md` exists for this story
**Date:** 2026-07-25

## Overview

Replace the SDLC plugin's whole-file agent memory diaries with per-rule files that are self-describing via YAML frontmatter and collected selectively at dispatch by a mechanical awk pass. This story ships the **protocol only** — the schemas, the collection contract, the lint gate, the maintenance op, and the ADR that records the standard; migrating any repo's existing memory content is NA-74.

## Data Model — memory artifact schemas

The "entities" here are on-disk markdown artifacts in the **consumer repo** (`.claude/memories/**`, `docs/adr/**`). The plugin defines the schemas; it does not ship the data.

### New entity — Rule entry

**Path:** `.claude/memories/agents/<agent>/<rule-id>.md` (per-agent) or `.claude/memories/agents/shared/<rule-id>.md` (cross-domain).
**Base:** plain markdown file with a YAML frontmatter block. Chosen over a single YAML/JSON database file because per-file granularity is what eliminates memory PR conflicts — two agents writing rules in the same story touch disjoint files, so there is nothing to merge.

| Field      | Type       | Nullable | Default  | Notes                                                                                                                       |
| ---------- | ---------- | -------- | -------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `id`       | `string`   | No       | —        | kebab-case; MUST equal the filename stem; unique across `.claude/memories/agents/**`                                         |
| `agent`    | `string[]` | No       | —        | SDLC agent names; length ≥ 1. Under `agents/<agent>/` MUST be exactly `[<agent>]`. Under `agents/shared/` MUST be length ≥ 2 |
| `trigger`  | `string[]` | No       | —        | 1–6 lowercase keyword phrases naming the situation the rule fires in                                                         |
| `rule`     | `string`   | No       | —        | ONE line, ≤ 200 chars, condition-action form: `When <condition>, <action>`                                                   |
| `evidence` | `string[]` | No       | —        | length ≥ 1; each item is a Jira key (`NA-26`), a PR ref (`PR#137`), or a 7–40 char commit SHA                                |
| `uses`     | `integer`  | No       | `0`      | incremented by the agent each dispatch in which it applied the rule                                                          |
| `status`   | `enum`     | No       | `active` | `active` \| `deprecated` \| `promoted` — only `active` is collected at dispatch                                              |

**Body:** optional, a single `## Why` section, ≤ 10 lines. Never read during collection — an agent opens the file only when the one-line `rule` is insufficient.

**Admission test.** A candidate is admitted as a rule entry only if ALL four hold:

1. **Generalized** — states a condition and an action that constrain future work, not a narrative of one story.
2. **Non-obvious** — not already derivable from the agent definition, the project override, or a repo `CLAUDE.md`.
3. **Falsifiable trigger** — you can name the concrete situation in which it fires (this is what populates `trigger`).
4. **Not already an accepted ADR** — no `status: accepted` ADR covers the same decision (T2 wins; write nothing).

Rejected by construction: story diaries, `Learnings/Pitfalls/Patterns` prose blocks, restatements of existing config, and any entry whose text only makes sense with the originating story in mind.

### New entity — Review round file

**Path:** `.claude/memories/reviews/<YYYY-MM-DD>-<STORY-KEY>.md`; a second review round for the same story on the same date takes the `-r2`, `-r3`, … suffix.

| Field         | Type       | Nullable | Default | Notes                                                                                     |
| ------------- | ---------- | -------- | ------- | ------------------------------------------------------------------------------------------- |
| `story`       | `string`   | No       | —       | Jira key; MUST match the key in the filename                                               |
| `date`        | `string`   | No       | —       | `YYYY-MM-DD`; MUST match the date in the filename                                          |
| `domains`     | `string[]` | No       | —       | SDLC agent names whose work the round touched; `[]` allowed only when `issue_count` is `0` |
| `root_causes` | `string[]` | No       | —       | tokens from the controlled vocabulary; `[]` allowed only when `issue_count` is `0`         |
| `issue_count` | `integer`  | No       | —       | count of Critical + Important findings in the round; `0` marks a clean review              |

**Body:** `## Issues`, `## Preventions`, `## Rules written` (list of rule `id`s created from this round). A clean review (`issue_count: 0`) writes frontmatter only — the body is omitted, and the file exists purely as the "this story was reviewed" marker that the analyze finding and the GC op key on.

### Relationships

- SDLC agent (1) → (many) Rule entry via the directory `agents/<agent>/` **and** the frontmatter `agent` list.
- Rule entry (many) → (many) SDLC agent via `agent[]` — a shared rule under `agents/shared/` names every agent it binds.
- Review round file (1) → (many) Rule entry via the body's `## Rules written` id list (soft reference, not enforced by lint).
- Jira story (1) → (many) Review round file via `story` + filename (one file per review round).
- ADR (1) → (many) SDLC agent via `agents[]`; an ADR with an empty/absent `agents` list binds every agent (the `General` audience).
- Rule entry (1) → (0..1) ADR via `status: promoted` — the promotion is one-way and terminal; a promoted rule is deleted by the maintenance op, never revived.

### Deleted entity

`.claude/memories/reviews/patterns.md` — the single append-only QA audit log is replaced by per-round files. This story stops writing it and adds the legacy detection; **deleting the existing file is NA-74.**

## Contract Surface

This story has no HTTP API. Its equivalent surface is three mechanical contracts (two scripts and one maintenance op) plus the agent-return contract. Every contract below has a column in the Permissions table.

### New contracts

| Contract                | Invocation                                                     | Caller                                 | Description                                                          |
| ----------------------- | -------------------------------------------------------------- | -------------------------------------- | ---------------------------------------------------------------------- |
| Memory collection       | `bash ${CLAUDE_PLUGIN_ROOT}/scripts/collect-memory.sh <agent>`  | every dispatched agent, first steps    | Emits the agent's applicable rule + ADR index lines on stdout         |
| Frontmatter lint        | `bash plugins/sdlc/scripts/check-frontmatter.sh [<repo-root>]`  | CI (`ci.yml`), and any agent pre-commit | Validates rule + review file schemas; non-zero exit fails the PR     |
| Memory maintenance op   | `${CLAUDE_PLUGIN_ROOT}/refs/memory-maintenance.md`              | `ai-enablement-engineer`, founder-gated | Decay/demotion, review-file GC, ADR-candidate nomination, T1 deletion |
| Rule-application report | `Rules applied:` line in the domain-agent return                | every dispatched agent → orchestrator  | Cites the rule ids the dispatch actually applied                      |

### Memory collection contract

**Implementation medium:** an awk pass wrapped in `plugins/sdlc/scripts/collect-memory.sh`. The 9 agent definitions carry a pointer to this one command, not an inlined awk snippet — the single-canonical-statement rule (ADR-0004) applies, and 9 copies of an awk program would drift on the first change.

**Sources scanned, in this order:**

1. `.claude/memories/agents/<agent>/*.md`
2. `.claude/memories/agents/shared/*.md`
3. `docs/adr/*.md` (excluding `index.md`)

**Mechanical filters (all applied by awk over frontmatter only — bodies are never read):**

| Source       | Filter                                                                                   |
| ------------ | ------------------------------------------------------------------------------------------ |
| rule entries | `agent` list contains `<agent>` AND `status` is `active`                                  |
| ADRs         | (`agents` list contains `<agent>` OR `agents` is empty/absent) AND `status` is `accepted` |

**Output shape** — one line per surviving artifact, on stdout:

```
RULE <id> [<trigger>, <trigger>] <rule>
ADR <NNNN> [<trigger>, <trigger>] <title>
```

The agent then does a second, judgement pass: match the emitted `trigger` phrases against its dispatch task and open the full file (rule body, or `docs/adr/NNNN-*.md`) **only** for the entries it will actually follow. Pass 1 is mechanical and cheap; pass 2 is selective. This is what makes per-dispatch cost track the index (~25 tokens per artifact) rather than the corpus.

**Legacy fallback.** If `.claude/memories/agents/<agent>.md` exists as a regular file (v1 flat diary), the script emits the whole file on stdout preceded by a `LEGACY` banner and writes a one-line warning to stderr. Exit stays 0 — a repo that has not yet migrated must keep working.

**Exit codes:** `0` in all normal cases including a wholly absent `.claude/memories/` tree (a repo with no memory yet emits nothing). `1` only when the `<agent>` argument is missing or empty.

### Frontmatter lint contract

**Path:** `plugins/sdlc/scripts/check-frontmatter.sh`. Modelled on the existing `check-agent-skill-preloads.sh` (bash, `set -uo pipefail`, `nullglob`, prints every offender then exits non-zero once).

Validates, over the repo it is run in:

| Target                            | Checks                                                                                                                                                                                                                                                                                                                                                                                     |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `.claude/memories/agents/**/*.md` | frontmatter present and parseable; all 7 rule fields present; `id` == filename stem; `id` unique repo-wide; `agent` non-empty and directory-consistent; `trigger` 1–6 items; `rule` one line ≤ 200 chars; `evidence` non-empty with each item matching a Jira-key / `PR#n` / SHA pattern; `uses` a non-negative integer; `status` in the enum                                                |
| `.claude/memories/reviews/*.md`   | filename matches `YYYY-MM-DD-<KEY>[-rN].md`; all 5 review fields present; `story`/`date` agree with the filename; every `root_causes` token exists in `root-cause-vocab.txt`; `issue_count` a non-negative integer; empty `domains`/`root_causes` allowed only when `issue_count` is `0`                                                                                                     |
| legacy artifacts                  | `.claude/memories/agents/*.md` as a **file**, or `.claude/memories/reviews/patterns.md` → WARNING on stderr, exit stays 0 (migration is NA-74, and the lint must not red-wall an unmigrated repo)                                                                                                                                                                                           |

**Exit codes:** `0` when every present artifact validates, or when `.claude/memories/` is absent entirely. `1` on any schema violation. Wired into `.github/workflows/ci.yml` as one additional `- run:` step alongside the existing plugin guards.

### Maintenance-op contract

**Path:** new ref `plugins/sdlc/refs/memory-maintenance.md`, executed by `ai-enablement-engineer`. Entered from the `memory-gc-overdue` analyze finding's apply path or by explicit founder instruction. Always founder-gated, always a reviewable PR — never a silent write.

Four operations:

| Op                       | Rule                                                                                                                                                                                                                                                   |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decay / demotion         | `status: active` + `uses: 0` + newest `evidence` older than the retention window → propose `status: deprecated`. Already `deprecated` and one further window elapsed → propose deletion.                                                                 |
| Review-file GC           | Delete a review file when (a) every id in its `## Rules written` is now `status: promoted`, or (b) it is an `issue_count: 0` marker older than the retention window, or (c) it wrote no rules and is older than the retention window.                    |
| ADR-candidate nomination | Nominate every rule with `uses >= 3` OR `agent` length ≥ 2; emit the candidate list (id, rule, evidence, uses) and hand it to `knowledge-engineer` for `/sdlc:docs distill`. Nomination never writes an ADR.                                            |
| T1 deletion-on-promotion | When distill lands an ADR that supersedes a rule, set the rule `status: promoted`, then delete it in the maintenance PR. **This moves off `knowledge-engineer`** — see the analyze-protocol change below.                                               |

**Retention-window semantics.** The `Review retention window` token accepts two fixed forms, parsed without heuristics:

- `<n> months` — wall-clock: an artifact is "older than the window" when its date (review file) or newest `evidence` story's merge date (rule entry) is more than `n` months ago.
- `<n> stories` — activity-based: an artifact is "older than the window" when ≥ `n` distinct story keys have been recorded in `.claude/memories/reviews/` since its date / newest `evidence` entry. Preferred for low-activity repos, where wall-clock decay would expire still-relevant rules between infrequent commits.

### Rule-application report contract

The domain-agent return format in `refs/domain-agent-handoff.md` gains one required line:

```
Rules applied: <rule-id>, <rule-id> | none
```

Complete returns become 4 lines, blocked returns 5. `none` is valid and expected when collection emitted nothing applicable. The agent increments `uses` and appends the current story key to `evidence` on each rule it cites, committing those edits with its domain work.

Two ownership carve-outs this story introduces, both to be written into `analyze-protocol.md`'s memory-ownership section:

- **Counter-only writes are not cross-agent writes.** Incrementing `uses` and appending a story key to `evidence` on a rule under `agents/shared/` is permitted for any agent that applied the rule. It changes no semantics, so it falls outside the cross-agent-write refusal.
- **QA rule authorship for the fixing agent.** `qa-engineer` Step 5 creates rule entries under `agents/<fixing-agent>/`. This is a newly sanctioned exception (the v1 equivalent — QA appending to another agent's diary — was already the de facto behaviour); it is bounded to _creating new rule files from that round's findings_ and never to editing or deleting existing ones.

## Error Handling

| Scenario                                                           | Behaviour                                                                                                                              | Exit / effect             |
| ------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- |
| `.claude/memories/` absent entirely                                | Collection emits nothing; lint passes                                                                                                  | 0                         |
| Legacy flat diary at `agents/<agent>.md`                           | Collection emits the whole file after a `LEGACY` banner + stderr warning                                                               | 0 (degraded, still works) |
| Legacy `reviews/patterns.md` present                               | Lint warns on stderr; analyze raises `legacy-memory-layout`                                                                            | 0                         |
| Rule file with unparseable or missing frontmatter                  | Collection skips it silently; lint fails and names the file                                                                            | lint 1                    |
| Rule `id` does not match filename stem, or duplicates another `id` | Lint fails and names both files                                                                                                        | lint 1                    |
| Rule under `agents/<agent>/` whose `agent` list omits that agent   | Lint fails                                                                                                                             | lint 1                    |
| Rule under `agents/shared/` with a single-agent `agent` list       | Lint fails (a single-agent rule belongs in that agent's dir)                                                                           | lint 1                    |

| Review filename disagrees with its `story`/`date` frontmatter      | Lint fails                                                                                                                             | lint 1                    |

| Collection invoked with no agent argument                          | Usage message on stderr                                                                                                                | 1                         |
| Agent applied a rule but omitted `Rules applied:`                  | Orchestrator treats the return as a contract violation and re-dispatches, exactly as it already does for a missing `Skills loaded:` line | dispatch failure          |
| Maintenance op proposes a deletion without founder confirmation    | Refused — the op has no auto-apply path                                                                                                | refused                   |

**Concurrency behaviour:** two agents writing rules in the same story write distinct files, so there is no merge surface. The only shared-file writes are counter-only `uses`/`evidence` edits on `agents/shared/` rules; a conflict there is a one-line frontmatter conflict resolved by taking the higher `uses` and the union of `evidence`.

## Out of Scope

- Migrating any repo's existing memory content — the ~5.1k lines of flat diaries and the 21 `patterns.md` entries in this repo are **NA-74**.
- Backfilling `trigger:` onto the 10 existing ADRs — NA-74.
- Deleting `.claude/memories/reviews/patterns.md` and the four flat agent diaries — NA-74.
- Running `/sdlc:docs distill` over the migrated corpus, and any ADR promotion resulting from it — the existing distill pipeline, post-migration.
- A generic migration framework, memory-format version markers, or migration chains — deferred until a v3 need exists (recorded as a deferral note in the ADR).
- Changes to T0 (claude-mem) behaviour, its MCP tools, or its local storage.
- Rolling the standard out to other consumer repos (EdgePDF and friends) — they update the plugin and run `/sdlc:analyze`; no per-repo story.
- Any change to `docs/adr/index.md`'s regeneration algorithm or its dev-facing role.
- Any web, mobile, database, or offline-sync work — this repo has no such workspace in scope for this story.

## Resolved Questions

All open questions were resolved during spec review (PR #182):

- **`trigger` matching in pass 2** — **semantic match by the agent** (founder-confirmed). `trigger` phrases are hints for the model's selection pass, not a machine-evaluated predicate; the only mechanical filters are `agent` and `status`.
- **Should `check-frontmatter.sh` also validate ADR frontmatter?** — **No, not in this story.** ADRs are `knowledge-engineer`-owned and `trigger` is unbackfilled until NA-74; adding ADR validation now would red-wall CI on day one. Revisit after NA-74 lands.
- **Where does the `uses` increment get committed when an agent applies a shared rule but changes nothing else?** — **Commit it with the domain work as usual;** if the dispatch produced no other change, skip the increment rather than raising an empty commit.
- **Retention-window format** — **fixed grammar with two accepted forms: `<n> months` or `<n> stories`** (founder-directed). `<n> months` measures wall-clock age; `<n> stories` measures activity — better suited to low-activity repos, where wall-clock decay would expire still-relevant rules between infrequent commits. The maintenance op parses either form without heuristics; semantics are defined under the maintenance-op contract.
- **Does `principal-engineer` need its own rule directory?** — **No.** It orchestrates and does not implement; its learnings belong to the playbook refs, which are versioned config, not memory.
