## The `$WORKTREE` path bug — load-bearing, and where the fix lives

On `/impl`'s full path the plan doc is merged to `<BASE-BRANCH>` and readable at `docs/superpowers/plans/<STORY-KEY>.md` from the primary checkout. On `/auto` **Workflow A** the plan doc is committed onto `feat/<STORY-KEY>` (`commands/auto.md:322`, step A2.2, verified) and **does not exist in the primary checkout** — the orchestrator's CWD for the whole run (`principal-engineer-playbook.md:240`). Handing the bare relative path there yields `ERROR=plan-not-found` **on every `/auto` story**.

**Amendment A1 — resolution lives in the script, not the playbook.** Script bytes are `+0` resident; playbook bytes have 242 B of slack. `plan-slice.sh` resolves in this order, first hit wins:

```text
resolve(p) := p                        WHEN [ -r "$p" ]
              "$WORKTREE/$p"           WHEN WORKTREE is set AND [ -r "$WORKTREE/$p" ]
              ERROR=plan-not-found     otherwise (exit 2)
```

The playbook still passes the explicit path it holds — belt and braces. The five-key contract is **unchanged**; resolution is observable through `SLICE=` on the fallback path and is asserted directly by **G-12**, which runs from a CWD where only the `$WORKTREE`-prefixed file exists and asserts exit 0 plus a correct slice. Removing the resolution flips G-12 to `ERROR=plan-not-found`. **Flagged for the review gate.**

## Grammar — corrected, pinned at `af45198`

```text
AGENT_SET       := database-administrator | platform-engineer | ai-enablement-engineer
                 | sync-engineer | web-engineer | mobile-engineer | knowledge-engineer
                 # principal-engineer is DELIBERATELY EXCLUDED — an orchestrator phase is no
                 # domain agent's to receive (NA-88.md / NA-89.md `## Phase 4 — … orchestrator`)
PHASE_HEADING   := ^##[ ]+Phase\b  AND  the line contains >= 1 AGENT_SET token
                 # decoration-insensitive: [x], `x`, (x), `[x]`, · `x` all match; the ordinal is
                 # OPTIONAL (NA-6, NA-15, NA-52, NA-62 carry ordinal-less phase headings)
SECTION_END     := next line matching ^##[^#] , or EOF
TASK_LINE       := ^[ \t]*[-*] \[[ xX]\][ \t]
FENCE_RULE      := a ^## line inside a ``` or ~~~ fence is NOT a heading
```

`FENCE_RULE` is load-bearing, not defensive: real plans quote the `tech-lead` template inside fenced blocks, and a fence-blind scanner truncates the slice at a fake heading. **Toggle on any line whose lstripped form starts with ``` or ~~~**, and count the toggles — do not try to match opening to closing fence lengths.

**Multiple phases per agent are normal and MUST all be returned.** **6 of 41** real plans assign more than one phase to a single agent. Phase mode concatenates every matching section **in document order** into one slice file, separated by a single blank line. Returning only the first is silent data loss (**G-4**).

### Fail-safe direction — always widen, never empty

| Condition | `GRAMMAR` | `SLICE` | `TASKS` | `PHASES` | Exit |
| --- | --- | --- | --- | --- | --- |
| ≥1 phase heading matches the requested agent | `matched` | tmp slice file | slice task count | whole-doc phase count | 0 |
| Doc has phase headings, none for this agent | `matched` | **the plan path itself** | whole-doc task count | whole-doc phase count | 0 |
| Doc has zero phase headings | `unmatched` | **the plan path itself** | whole-doc task count | `0` | 0 |
| `checklist` mode | `matched`\|`unmatched` | tmp checklist file | checklist line count | **`0` always** | 0 |
| Plan path does not resolve | — | **not emitted** | — | — | 2 |

An empty slice is never a valid output. `TASKS=0` with a tmp-file `SLICE` is unreachable by construction and, if observed, is an orchestrator STOP.

**The unmatched path is not rare and is not a failure.** 10 of 41 plans take it. It is still a **win**: it emits a *path* where today's instruction pastes *content*. The paste→path move is the value; slicing is the bonus. A grammar the slicer fails to recognise degrades NA-81 to its floor, never below today.

## `plan-slice.sh` — CLI and stdout contract (verbatim)

```text
bash plugins/sdlc/scripts/plan-slice.sh <plan-path> phase <agent-name>
bash plugins/sdlc/scripts/plan-slice.sh <plan-path> checklist
```

Success — **exactly five lines**, every value single-quoted at emission:

```text
MODE=phase|checklist
SLICE=<absolute path to the slice file, OR the resolved plan path itself on fallback>
TASKS=<integer — count of task lines inside SLICE>
PHASES=<integer — phase headings matched in the whole doc; 0 in checklist mode>
GRAMMAR=matched|unmatched
```

Failure — **exit 2, and no `SLICE=` key is emitted**:

```text
ERROR=plan-not-found|bad-mode|bad-args
```

| Exit | Condition | stdout |
| --- | --- | --- |
| 0 | usable output produced (including every fallback) | full 5-key block |
| 2 | plan path does not resolve, unknown mode, or wrong arg count | `ERROR=` only |

**Consumer form (verbatim — the only correct one):**

```text
out=$(bash ${CLAUDE_PLUGIN_ROOT}/scripts/plan-slice.sh "$PLAN" phase "$AGENT") || STOP
unset MODE SLICE TASKS PHASES GRAMMAR
eval "$out"
[ "${TASKS:-0}" -gt 0 ] || STOP
```

**Why not `eval "$(bash …)" || STOP`:** command substitution swallows the child's exit status, so the `||` tests `eval`'s status — which is the last assignment's, always 0. The exit-2 contract would be **invisible**. The `unset` is not decoration either: Step 4 loops over N phases and a stale `SLICE` from the previous phase is a silently-wrong dispatch.

**Slice files land under `$(tmp-dir.sh)` = `./.tmp/<session-key>` relative to CWD.** `.tmp/` is gitignored (`.gitignore:61`) and both integrity checks use `git status --porcelain` **without** `--ignored` (`assert-workspace-clean.sh:51,86`; `principal-engineer-playbook.md:422`), so slices are invisible to PE Step 5's primary-checkout assert and QA Step 3's stray-file check. The orchestrator's CWD is the primary checkout for the whole run, so slices land in the primary's `.tmp/` and survive Step-7 worktree teardown, which a worktree-local `.tmp/` would not. `cleanup-tmp.sh` reaps the dir at `SessionEnd` (`hooks/hooks.json:18`). **No `--out-dir` flag** — one fewer knob, one fewer way to write into a worktree.

- [ ] **Step 1: Implement the fence-aware line scan**

One pass over the resolved plan. Track fence state; classify each non-fenced line.

```text
in_fence := 0
FOR each line:
  lstripped starts with ``` or ~~~ -> in_fence := 1 - in_fence ; CONTINUE
  in_fence == 1 -> CONTINUE
  line matches ^[ \t]*[-*] \[[ xX]\][ \t] -> doc_tasks += 1
  line matches ^##[ ]+Phase\b AND contains >=1 AGENT_SET token -> phase heading
      phases += 1 ; owners := the AGENT_SET tokens present in the line
  line matches ^##[^#] -> ends any open section
```

`AGENT_SET` is the seven names in the **Grammar** section. **`principal-engineer` is not one of them.** Membership is a plain substring test on the raw heading line, which is what makes all five decoration forms match without five regexes.

- [ ] **Step 2: Phase mode — concatenate every matching section in document order**

```text
sections := every phase section whose owners contain <agent>, IN DOCUMENT ORDER
sections non-empty -> write them to $(tmp-dir.sh)/plan-slice.<key>.<agent>.<pid>.md,
                      separated by ONE blank line
                      emit phase <abs slice path> <task lines in slice> <phases> matched
sections empty AND phases > 0 -> emit phase <resolved plan path> <doc_tasks> <phases> matched
phases == 0                  -> emit phase <resolved plan path> <doc_tasks> 0 unmatched
```

**Returning only the first matching section is silent data loss** — 6 of 41 real plans give one agent more than one phase. G-4 exists for this.

A section runs from its heading line **through the line before the next `^##[^#]`** (fence-aware), or EOF. The heading line itself is **included** in the slice — G-3 asserts the slice's first line is the exact heading string.

- [ ] **Step 3: Checklist mode**

```text
lines := every TASK_LINE in the whole doc, in document order, fence-aware
lines non-empty -> write to $(tmp-dir.sh)/plan-checklist.<key>.<pid>.md
                   emit checklist <abs path> <count> 0 <matched|unmatched by phases>
lines empty     -> emit checklist <resolved plan path> 0 0 unmatched
```

`PHASES` is **always 0** in checklist mode — that is the contract, not an oversight.

The consumer's CWD may differ from the slicer's.
