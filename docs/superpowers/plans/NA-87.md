- [ ] **1.1 `platform-engineer`** Create `tools/sdlc-analyser/artifact-contract.sh` — the extraction engine and `--extract` mode. POSIX-portable bash, `set -uo pipefail`, same header-comment convention as `branch-inventory.sh` (`# artifact-contract.sh — see tools/sdlc-analyser/README.md for the extraction rule.`), same `repo_root` derivation.

      **The content-contract extraction rule (verbatim from the spec — implement exactly this).** A contract item is any of, **in file order**:

      1. **heading** — every ATX heading (`#`…`######`), taken verbatim **including its level**.
      2. **field** — every `<key>:` at the start of a trimmed line inside a fenced ` ```yaml ` block.
      3. **fence** — every fence's info string (` ```bash `, ` ```typescript `, …), counted **once per fence**.
      4. **literal** — every backtick-quoted inline span that is a path, a command, or an ALL-CAPS token (`STOP`, `blocked`, `N/A`).

      **Prose is NEVER a contract item** — that is exactly the surface workstream B is allowed to compress.

      Sub-rules this plan pins so the rule is mechanically decidable (record all of them in the README at Task 1.4):

      - The extractor **descends into fences** — a `## Overview` line inside a ` ```markdown ` template fence **is** a heading item. Fences are content, not skipped regions.
      - A document-**leading** `---` … `---` YAML frontmatter block is treated as a ` ```yaml ` fence for rule 2, and contributes **no** fence item of its own. (Required: produced rule entries and review-round files carry frontmatter, their templates carry ` ```yaml ` fences.)
      - `literal` classification of a backtick span, first-match-wins: **path** = contains `/` and no whitespace; **command** = first whitespace-separated word ∈ `{bash, git, gh, acli, pnpm, npm, npx, python3}`; **ALL-CAPS token** = matches `^[A-Z][A-Z0-9_]*$` with length ≥ 2. Anything else is not an item.
      - An empty-info fence (` ``` `) yields a fence item with value `` (empty string) — it still occupies a position.

      **Section and fence selectors (gap fill — flag in the PR body).** The spec's one-template-one-artifact contract is unsatisfiable as stated for all five surfaces: four of the five templates are a *sub-section* of a larger file (and three are a fenced block inside that sub-section), so whole-file extraction would emit items no produced artifact can ever contain. Two optional selectors close it, and nothing else changes:

      - `--section "<exact heading text>"` — restrict extraction to the span from that ATX heading (heading itself **excluded**) to the next heading of the **same or higher** level. Unknown heading → error naming the heading, **exit 2**.
      - `--fence <n>[,<n>...]` — within the selected span (or the whole file when `--section` is absent), select the *n*-th fenced block(s), 1-based in file order, and extract from their **contents only**; the selected fences' own info strings are **not** items. Multiple indices are extracted in ascending file order. An out-of-range index → error naming the index and the count found, **exit 2**.

      `--extract` output format, one item per line, exactly: `<kind>:<line>:<value>` — `kind` ∈ `heading | field | fence | literal`, `line` is the 1-based line number in the **source file** (not the span), `value` is the item verbatim. `kind` and `line` never contain `:`, so a consumer splits on the first two colons.

- [ ] **1.2 `platform-engineer`** Add the diff mode to `tools/sdlc-analyser/artifact-contract.sh`: `--template <t> [--section …] [--fence …] --artifact <a>`. The artifact side is always extracted **whole** (no selectors apply to `--artifact`).

      **Comparison is positional and order-sensitive.** Walk the template's ordered item list against the artifact's ordered item list. Item *i* matches when `kind` is equal **and** the values match, where a template value containing a placeholder — `[...]`, `<...>`, or the literal `NNNN` — matches **any** artifact value of the same kind at that position. A template item with no match at its position is **missing**.

      Output shape — one `KEY=value` per line, same shape as `branch-inventory.sh`:

```text
TEMPLATE=plugins/sdlc/skills/writing-specs/SKILL.md
ARTIFACT=docs/superpowers/plans/NA-87-measurements/ref-spec.md
CONTRACT_TEMPLATE=14
CONTRACT_ARTIFACT=14
CONTRACT_MISSING=
CONTRACT_MATCH=true
```

      - `CONTRACT_TEMPLATE` — count of items extracted from the template (after selectors).
      - `CONTRACT_ARTIFACT` — count of those matched in the artifact.
      - `CONTRACT_MISSING` — ordered `;;`-separated list of `<kind>:<value>` for each unmatched template item; **empty string** when none.
      - `CONTRACT_MATCH` — `true` iff `CONTRACT_MISSING` is empty.

      Exit codes, exactly: **0** = `CONTRACT_MATCH=true`; **1** = mismatch; **2** = a path is unreadable or a selector does not resolve — in that case emit `CONTRACT_ARTIFACT=-1` plus a one-line `REASON=<what failed>` and let the author supply a manual count. **The non-zero exits are consumed by the author, not by CI (D7).**
