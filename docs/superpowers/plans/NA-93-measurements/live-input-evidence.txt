== THE CORRECTION — "186 snapshots / 9 distinct tuples" is a superseded, un-deduplicated figure ==

baseline (Global Constraints, Task 3.2 Step 3). That figure is an UN-DEDUPLICATED grep estimate:
each `loop-status:` probe event is stored TWICE in the same JSONL record — once in
`message.content`, once in `toolUseResult.stdout`, byte-identical — so a naive `grep -c
loop-status:` over the corpus counts every event twice. This was independently confirmed: 98
records in this corpus carry the marker in BOTH fields.

event regardless of how many fields within it repeat the marker) is 97 snapshots / 10 distinct
tuples — the extra distinct tuple beyond the spec's 9 is corpus growth since the spec's baseline
was measured, which the plan (Task 3.2 Step 3) explicitly allows: "A count that has GROWN is not
automatically a failure ... Record the actual numbers verbatim."

is the load-bearing conclusion, and it holds identically whether the snapshot count is read as 186
