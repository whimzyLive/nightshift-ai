# Memory v2 — frontmatter-triggered rule memory + injection standard — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Spec:** [docs/superpowers/specs/NA-73.md](../specs/NA-73.md)
**Story:** NA-73 — Memory v2: frontmatter-triggered rule memory + injection standard (plugin protocol). No parent Epic. Blocks NA-74.
**Date:** 2026-07-25
**Agents required:** `ai-enablement-engineer`, `platform-engineer`, `knowledge-engineer`
**Complexity:** Medium (3 phases)

**Goal:** Replace the SDLC plugin's whole-file agent memory diaries with per-rule frontmatter files collected selectively at dispatch by a mechanical awk pass — shipping the protocol only (schemas, collection contract, lint gate, maintenance op, ADR).

**Architecture:** Two new bash/awk scripts under `plugins/sdlc/scripts/` define the mechanical contracts (collection + lint). Every behavioural change to the pipeline is a prose edit in `plugins/sdlc/refs/**`, `plugins/sdlc/agents/**`, and `plugins/sdlc/commands/init.md` that points at those two scripts rather than restating them (ADR-0004, single canonical statement). One CI line runs the lint. One ADR records the standard.

**Tech Stack:** Bash + awk (no other runtime), YAML frontmatter in markdown, GitHub Actions, Nx (`pnpm nx run-many -t test`), Prettier (in-tree idempotency check per ADR-0002).

## Global Constraints

Every task's requirements implicitly include this section. Values are copied verbatim from the spec.

- **Migration is NOT this story.** NA-74 owns migrating existing memory content, backfilling `trigger:` onto the 10 existing ADRs, and deleting `.claude/memories/reviews/patterns.md` + the four flat diaries. This story adds detection and legacy fallback only. **Never delete or rewrite any existing `.claude/memories/**` content.**
- **Rule entry frontmatter — exactly 7 fields:** `id` (string, kebab-case, MUST equal filename stem, unique across `.claude/memories/agents/**`), `agent` (string[], len ≥ 1), `trigger` (string[], 1–6 lowercase keyword phrases), `rule` (string, ONE line ≤ 200 chars, `When <condition>, <action>`), `evidence` (string[], len ≥ 1), `uses` (integer, default `0`), `status` (`active` | `deprecated` | `promoted`, default `active`).
- **Review round frontmatter — exactly 5 fields:** `story` (Jira key), `date` (`YYYY-MM-DD`), `domains` (string[]), `root_causes` (string[] from the controlled vocabulary), `issue_count` (integer).
- **`SdlcAgentName` union (9 names):** `ai-enablement-engineer`, `database-administrator`, `knowledge-engineer`, `mobile-engineer`, `platform-engineer`, `principal-engineer`, `qa-engineer`, `sync-engineer`, `web-engineer`.
- **`principal-engineer` gets NO rule directory** (resolved question). It orchestrates; its change is dispatch-template + return-contract only, and it never invokes collection.
- **`trigger` matching is semantic, by the agent** (resolved question). The only mechanical filters are `agent` and `status`. Never implement `trigger` as a machine-evaluated predicate.
- **`check-frontmatter.sh` does NOT validate ADR frontmatter in this story** (resolved question) — `trigger:` is unbackfilled until NA-74; validating it now would red-wall CI on day one.
- **Retention window accepts exactly two forms, parsed without heuristics:** `<n> months` (wall-clock) or `<n> stories` (activity-based). Default `6 months`.
- **`uses` increments commit with the domain work** (resolved question). If the dispatch produced no other change, skip the increment rather than raising an empty commit.
- **ADR-0004 (single canonical statement with pointers):** agent definitions carry a pointer to `${CLAUDE_PLUGIN_ROOT}/scripts/collect-memory.sh`, never an inlined awk snippet. `qa-engineer-playbook.md` points at `refs/root-cause-vocab.txt`, never restates the token list.
- **ADR-0002 (in-tree prettier idempotency):** every markdown file touched must survive `pnpm exec prettier --check` unchanged. **ADR-0003 (column-0 dedent for list-adjacent fences):** fenced blocks adjacent to list items start at column 0.
- **Scope fence — `.github/workflows/ci.yml` gets exactly ONE new line** (the `check-frontmatter.sh` run). Do not wire any second CI step in this story.
- **No web, mobile, database, or offline-sync work.** Those phases are omitted deliberately.
