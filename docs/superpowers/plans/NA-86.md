# Shrink SDLC plugin instruction surface — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Story:** NA-86 — Shrink SDLC plugin instruction surface
**Spec:** [docs/superpowers/specs/NA-86.md](../specs/NA-86.md)
**Epic:** NA-76 — SDLC token and cost optimisation programme (workstream A)
**Date:** 2026-07-31
**Branch:** `feat/NA-86` (off `develop`)
**Agents required:** `platform-engineer`, `ai-enablement-engineer`
**Complexity:** High — 5 sequential phases, 2 agents, 4 spec slices

**Goal:** Re-encode and lazy-load the SDLC plugin's own instruction files (A1, A2/A3, A5–A9, A10) so an 8-point story's instruction load trends toward the programme's ≤230,000-token gate, without changing what any `/sdlc:*` command or agent does.

**Architecture:** Four spec slices land in order on one branch. Slice 1 ships the measurement instrument (`tools/sdlc-analyser/`) and the zero-semantic-risk table unpad + prettier-ignore. Slices 2 and 3 split the three largest instruction files into a fast path plus lazily-loaded refs and extract duplicated bash into three new scripts. Slice 4 closes the story by moving design rationale out of the loaded surface into ADRs and non-loaded design notes.

**Tech Stack:** Markdown, Bash (POSIX-portable, gated by `tools/portability-lint.sh`), Python 3 stdlib-only, GitHub Actions, Prettier 3.6.2, `acli`, `gh`.

## Global Constraints

Every task's requirements implicitly include this section. Values are copied verbatim from the spec.

- **No behavioural change.** No step added, removed, reordered, or given a different outcome. Encoding, packaging and load timing only. If a diff changes the order, count, or outcome of any step, it is out of scope for NA-86 regardless of how many tokens it saves.
- **A converted file must not change its own step count, step order, or step outcomes.**
- **Never hand-bump** `plugins/sdlc/.claude-plugin/plugin.json` — `nx release` owns versioning post-merge.
- Every touched shell script must pass `bash tools/portability-lint.sh`.
- Python is Python 3, **stdlib only**.
- Markdown + Shell, **kebab-case** filenames.
- No informative/explanatory code comments beyond what `plugins/sdlc/refs/code-comments-policy.md` allows.
- **Invocation rule (non-negotiable):** every script call site must be a single `bash <path> <args>` form — never wrapped in backticks, never built by string interpolation. `$(...)` capture is permitted **only** in the established `eval "$(bash …)"` shape already used by `plugins/sdlc/scripts/read-review-config.sh`. Rationale: the Bash permission matcher statically parses the command; an unparseable form falls through to an interactive ASK prompt regardless of allowlisting (`refs/permission-prompt-audit.md`, root cause #1).
- **No pseudocode block may use a ` ```bash ` fence** (something might execute it) — use a plain or ` ```text ` fence.
- Every extracted ref must be reachable from its parent by an **explicit path** — no "see the split file" without the path.
- Every rationale extraction leaves a `# rationale: <path>` pointer at the extraction site.
- `estTokens = bytes / 3.7`, floored.
- The analyser tools **read** transcripts and the repo. They must never write to the repo or to `~/.claude/`.
- **Excluded from every edit and from inventory totals:** vendored `skills/find-skills/` and `skills/skill-creator/` (23,942 tok).
- **Out of scope:** `plugins/gtm/**`; A4 (`refs/docs-pipeline.md` split, delivered by NA-79); sibling workstreams NA-87…NA-93; an automated measurement harness; prompt-caching work.
- **Cache hit rate is a constraint to protect, not a lever to pull** — must stay ≥ 94%.
- **A change that cuts tokens but raises QA rounds or blocked rate cost more than it saved** — revert it, do not argue it.

## Delivery-shape note — read before starting (deviation from the spec, flag at review)

The spec specifies **4 PRs**, each carrying its own before/after measurement block (AC-5: "no single lumped measurement stands in for the whole story"). `/auto` Workflow A Phase 2 raises **one combined plan+impl PR** for `feat/NA-86`.

**Reconciliation used by this plan:** the four spec slices are preserved as four ordered, separately-committed phase groups on the one branch, and **each slice produces its own distinct AC-5 measurement block** pasted into the single PR body — four blocks, headed `NA-86 S1`, `S2`, `S3`, `S4`. Slice S2 ships **two** new scripts (`loop-budget.sh`, `resolve-ai-workflow-mode.sh`) and therefore two test scripts. This plan reads the rule as **one line per new test script**; S2 adds two lines. - [ ] **1.1 `platform-engineer`** Create `tools/sdlc-analyser/instruction-inventory.sh`. Two modes over `plugins/sdlc/**/*.md` (plus `commands/`, `agents/`, `refs/`, `skills/`, `scripts/` for the `category` field):
      - **inventory mode (default):** one row per file — `path` (repo-relative), `bytes`, `estTokens` (`bytes / 3.7`, floored), `category` ∈ `command | agent | ref | skill | script | other`, `vendored` (`true` for `find-skills` and `skill-creator`; vendored rows are **excluded from totals**), `paddedContentRows: 0`, `paddedDelimiterRows: 0`.
