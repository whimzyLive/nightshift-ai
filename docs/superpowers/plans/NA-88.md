## The canonical C1 clause (written once here — Task 2.1 copies it, Task 2.5 asserts on it)

**867 bytes** measured as the test measures it (from the `## Context reuse` heading line through the last line before the next `## ` heading), inside the 900-byte budget with 33 bytes of headroom. Copy it byte-for-byte; if a wording change is unavoidable, re-measure before committing.

````text
## Context reuse

```text
path already read in full in this transcript -> never read it again
Edit/Write returned success -> no confirming read   # Edit/Write fail loudly; a read after a successful edit verifies nothing
earlier read was windowed AND another region is needed -> read ONLY the missing region with offset/limit
```

Carve-outs — a re-read here is correct, not a violation:

```text
a git op (checkout, merge --ff-only, fetch+reset) changed the tree since the read -> re-read
the earlier read was reported truncated -> re-read
the earlier read happened in a DIFFERENT transcript -> read normally   # a dispatched agent's context is empty; a ledger names paths, it never supplies their content
```

Precedence: correctness wins. Cannot establish the current content of a file you must edit -> read it. An unnecessary read is cheap; a wrong edit is not.
````

- [ ] **1.2 `platform-engineer`** Create `tools/sdlc-analyser/duplicate-reads.py` (C5). Python 3, **stdlib only, 3.9-compatible**, read-only. Mirror `cache-analysis.py`'s structure and CLI conventions exactly (positional `<label>` then transcript paths, `--per-story`, `resolve_paths` fail-loud, `main(argv)` returning an int):

```text
python3 tools/sdlc-analyser/duplicate-reads.py <label> <transcript.jsonl>... [--per-story] [--json]
```

      **The read-classification rule — implement exactly this, first-match-wins, top to bottom.** Within one transcript, for each `Read` tool-use in file order, with `whole := offset is None AND limit is None` and a window's extent `[offset or 1, (offset or 1) + (limit or 2000) - 1]`:

```text
no earlier read of this path -> first read
any earlier read of this path was whole -> redundant                       # the whole file is already in the transcript
this read is whole AND an earlier read of this path exists -> redundant     # supersedes the earlier window, re-bills it
window intersects an earlier window of this path -> overlapping
otherwise -> disjoint                                                      # legitimate: a new region of a file read in parts
```

      - **Locating a `Read` call:** each line is one JSON record; iterate `record["message"]["content"]` when it is a list and take every item with `type == "tool_use"` and `name == "Read"`; the path is `item["input"]["file_path"]`, the window `item["input"].get("offset")` / `item["input"].get("limit")`. Paths are compared as given, after `os.path.expanduser` — no realpath resolution (a symlink alias is not a duplicate we can prove).
      - **Transcript partition (D9 + gap fill, flag in the PR body).** The spec's unit is one `.jsonl` file. In this harness a subagent's records can share a file, distinguished by `isSidechain: true`; partition the classification state by **`(file path, bool(record.get("isSidechain")))`** so an orchestrator read and a subagent read of the same path are never counted as a duplicate. This implements D9's binding rule (*"a subagent's context genuinely does not hold the orchestrator's reads"*) on this harness's actual record shape; record the deviation from the spec's literal "separate files" wording in the README and the PR body.
      - **Categories** — exactly the four `DuplicateReadCategory` values, derived from the path, first-match-wins: `plugin-instruction` (contains `plugins/sdlc/` **or** resolves under a plugin cache path — match `/plugins/` plus `/sdlc/`), `self-generated-artifact` (contains `docs/superpowers/` or `.claude/memories/`), `project-config` (contains `.claude/` or a repo-root `CLAUDE.md`/`AGENTS.md`), `source-other` (everything else).
