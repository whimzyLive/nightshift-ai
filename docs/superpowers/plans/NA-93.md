## Read this first — H ships a SCRIPT, not a Haiku subagent

The story title says "Route loop passes to Haiku model". AC-1 says the probe-and-decision body is "routed to a cheap (Haiku-class) subagent". **H ships a deterministic script instead.** Founder ruling at the spec gate, 2026-08-01, carried into the merged spec's first section and into ADR 0020.

```text
the decision table is a pure function of a bounded integer tuple   # 1,458 enumerable cases
a script is exactly equivalent, costs ~0 context, and cannot mis-decide
a script is +0 on instruction surface -> it is EXECUTED, never READ
routing to a model buys nothing and adds a failure mode -> merging an unreviewed PR, or halting a healthy one
therefore: cheap := a script, not a cheap model
```

Precedent: NA-92's G3 shipped `scripts/docs-sync-gate.sh` over a subagent dispatch for the same reason, recorded in ADR 0019. **State the deviation plainly in the PR body.** It is not hidden behind "satisfies AC-1".

**The five decisions below are taken and are NOT re-openable by the implementer.**

| # | Decision | Rationale | Where it lands |

## The decision domain — the contract every artifact shares

**Copilot input line** (verbatim, `pr-loop-status.sh:14`):

```text
loop-status: copilot-reviewed-head=<rh> copilot-changes-requested=<cr> copilot-pending=<cp> unresolved-copilot=<un> checks-pending=<pend> checks-failing=<fail> checks-passing=<pass> copilot-reviewed-any=<ra>
```

**In-session input line** (verbatim, the CI-1 progress print):

```text
reviewed-head=<rh> review-clean=<rc> unresolved=<un> checks-pending=<pend> checks-failing=<fail>
```

**Domain enumeration** — only the 0 / 1 / >1 distinction is load-bearing for the count fields:

```text
copilot    := rh∈{0,1} × cr∈{0,1} × cp∈{0,1} × ra∈{0,1} × un∈{0,1,2} × pend∈{0,1,2}
              × fail∈{0,1,2} × pass∈{0,1,2}                      = 2^4 · 3^4 = 1,296
in-session := rh∈{0,1} × rc∈{0,1,'-'} × un∈{0,1,2} × pend∈{0,1,2} × fail∈{0,1,2} = 2 · 3^4 = 162
total      := 1,458 cases
```

**`review-clean='-'` is a LEGITIMATE value, not a parse failure.** CI-1 sets `LAST_REVIEW_CLEAN=-` (and resets the head to `-`) when the marker is absent or half-written. The "non-numeric field → unresolvable" fail-safe **must exempt `review-clean=-`** — otherwise 54 of the 162 in-session cases collapse to `unresolvable` and the enumeration measures nothing. The pair `(reviewed-head=1, review-clean=-)` is enumerable but production-unreachable, and both the extractor and the script must select **CI-f** for it. State this in the script header.

**Rule → DECISION mapping (verbatim contract, both artifacts):**

| RULE | DECISION | GRACE | RE_REQUEST |
| --- | --- | --- | --- |
| 1 | wait | no | no |
| 2a | wait | no | **yes** |
| 2b | wait | **yes** | **yes** |
| 3 | fix | no | no |
| 4 | clean | no | no |
| 5 | wait | no | no |
| 6 | halt | no | no |
| 7 | halt | no | no |
| CI-a | wait | no | no |
| CI-b | review | no | no |
| CI-c | fix | no | no |
| CI-c2 | halt | no | no |
| CI-d | clean | no | no |
| CI-e | halt | no | no |
| CI-f | halt | no | no |
| unresolvable | **wait** | no | no |

`checks-passing` is read by **no** rule. Rule selection is therefore invariant in `pass` across all 1,296 Copilot cases — a property Task 1.3 asserts, and a property that fails the moment a row starts reading it.
