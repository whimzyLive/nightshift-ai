## Issues

- Critical: the branch failed the required `check-frontmatter.sh` CI gate — a new rule file's `rule:`
  field was 289 chars against the 200 cap. The phase-4 return had reported that same gate as `OK`;
  the gate had been run **before** the memory file was written, so a stale pass was reported as a
  fresh one. Base was green, head was red. The sibling branch hit the identical cap one commit
  earlier (`31f49dc`).
- Important x4: the grep guard meant to prevent recurrence was defeatable by three valid `acli`
  spellings — `--project 'ABC'`, `--project=XYZ`, and `-p ET` (the short form is documented in this
  plugin's own `skills/acli/SKILL.md:76`); `agents/product-manager.md` never declared
  `<PROJECT-KEY>` even though that agent — not the command — runs the `acli create`, so a
  paraphrasing dispatch would hand it an unresolved token with no STOP attached; a ~50-line
  why-header in the new test duplicated rationale already written to a rule file, and the two had
  already diverged; the test's plugin-root resolution re-appended a literal `sdlc` and combined with
  `|| true` would let case 1 pass **vacuously** against a wrong root.
- Minor x4 (fixed): a false "never matches a documentation mention" claim in the test header; a
  memory rule overclaiming "survives reflow" when it survives only line-wrap; case 2 passing a
  **negated** instruction ("do not stop — default to `ET`"); the `-p` branch false-positiving on
  `mkdir -p SOMEDIR`, which already appears 4x in the scanned scope and is safe today only because
  those operands happen to be lowercase.

## Preventions

- Re-run every gate **after** the final edit and report what that run printed. A verification claim
  that does not match the tree is worse than no claim — it suppresses the check the coordinator
  would otherwise run. This round, one stale `check-frontmatter: OK` nearly shipped a red branch.
- A guard is only as general as its weakest accepted spelling. Before claiming a grep guard prevents
  a defect class, enumerate every syntax the underlying CLI accepts — short flag, `=` form,
  single/double quotes, **and this repo's own backtick convention** — and mutate each one.
- When fixing a hardcoded value, sweep the whole file for the same class before stopping at the
  reported line. NA-78's ticket named one literal; the file held a second (`ET-\d+` in the
  mode-detection regex) that broke epic-key recognition the same way.
- Put the token declaration and its STOP rule in the **agent** that issues the call, not only in the
  command that dispatches it. A command-only contract survives exactly as long as the dispatch
  prompt quotes it verbatim.
- A false-positive-prone guard is a future outage: `mkdir -p SOMEDIR` would have failed CI claiming
  a hardcoded Jira key. Qualify a short-flag match by the tool it belongs to.
