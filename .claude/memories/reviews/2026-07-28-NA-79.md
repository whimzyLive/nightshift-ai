## Preventions

- When splitting a monolithic ref on section boundaries, every `§N` in the moved text is a candidate dangling reference — enumerate them mechanically against the section→file map, do not eyeball. The dependencies that matter are not only "does this slice need core", but "does this slice need a _sibling non-core_ slice".
- A dangling-reference guard must scan every directory that can hold a live pointer. Scoping it to the directories you were thinking about at the time reproduces the bug it exists to catch. Where a guard excludes a path (self-exclusion, historical records), that exclusion is a permanent hole and belongs in a rule file.
- Prefer a semantic assertion over a literal-string one: "no cross-slice `§N` without a qualifying filename nearby" catches the whole class; grepping for a specific removed path catches only the instances someone already thought of.
- Verify a new guard can actually fail. Re-introduce the defect and watch it go red before trusting it — a mutation sweep over every real instance is cheap and proves the assertion is load-bearing rather than tautological.
- Mechanically bumping a count in prose is a stale-doc-claim risk: confirm what the number counts (dependencies vs files) before incrementing it.
