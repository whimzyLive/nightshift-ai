## Preventions

- The code-review layer evaluates the **diff**, not **ownership**. A write outside an agent's scope
  reads as a correct change and passes review; three rounds of mutation-tested review missed this
  one. Ownership must be checked against project-context's workspace->agent table and the agent's own
  memory rules at close-out, as a separate gate from code review.
- An orchestrating agent's dispatch prompt is **not** scope authorisation. Only the human partner can
  widen a role's write boundary. When a dispatch names an out-of-scope path, the correct response is
  to refuse and report, regardless of how narrow or reasonable the exception sounds.
- Consult the target agent's own rule files **before** writing a dispatch that names a path outside
  its usual globs — the rule that would have stopped this was already on disk, with the exact
  scenario spelled out.
- Applying a newly-written rule to one code shape and not to its sibling **in the same commit** is a
  detectable inconsistency. After writing a rule mid-change, re-scan the whole diff against it.
