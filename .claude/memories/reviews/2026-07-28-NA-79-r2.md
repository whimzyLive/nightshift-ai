## Issues

- **Important — the change-size gate's fifth outcome bucket mandated a `Docs sync:` report string that Step 8's own template did not enumerate.** Step 6.5 required the orchestrator to emit `Docs sync: no manifest-tracked files touched — skipped` at two sites (the gate prose and the new table row), while Step 8's report template still listed four options and described them as "the two no-op-or-success paths". An orchestrator following Step 8 literally had no valid token for the new bucket and would fall back to `skipped (no docs manifest)` — factually wrong, since that bucket is reached only when the manifest is present and passed its gate. Fixed by adding the fifth option to the template and correcting the count.

## Preventions

- Adding a bucket, branch, or outcome to a contract table is not done when the table is updated — every downstream consumer of that table's output vocabulary has to accept the new token. In this repo the report template at the end of a playbook is the consumer that is easiest to miss, because it sits far from the section that grew.
- When a spec mandates a literal string, the fix must reuse that exact string rather than paraphrase it. Two sites disagreeing about the token is worse than one site missing it, because the disagreement is silent.
- Two prior review passes on this same PR verified the gate section itself and missed this — they scoped to the changed hunks. A finding can live entirely in unchanged lines that the change invalidates, so a review of a contract edit should follow the contract to its consumers, not stop at the diff boundary.
