## Preventions

- A guard's placement is judged by **guard-to-call ratio, not proximity in the file**. One guard
  above a loop of N calls is one verification for N calls. Two mutually-exclusive branches sharing a
  preceding guard is 1:1 and fine — the distinction is the ratio, not how close the lines look.
- When a fix adds a guard invocation to N call sites, sweep the file's own **reference/example**
  blocks too — they are copied by consumers and are call sites in practice.
- An assertion that two outputs merely _differ_ is vacuous whenever the outputs interpolate distinct
  inputs. Assert on the wording that encodes the behaviour, then mutate the branch away and confirm
  the case dies.
- Comparing a human-typed config value against a machine-reported one requires normalisation
  (case, scheme, trailing slash) or the guard bricks every call with an unactionable remedy. Two
  existing scripts in this repo already normalise; match them rather than inventing a third parser.
- Prompt-layer guards (`|| exit 1` inside a markdown fence) are **advisory on the model** when the
  guard and the guarded call are separate tool invocations. Only guards inside shell scripts are
  mechanically enforced. Prefer the script-level site when both are available.
