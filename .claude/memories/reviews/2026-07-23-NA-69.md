## Issues

- Critical (AC-gap): `template.tsx` (route enter transition) read the reduced-motion flag via a
  post-mount `useEffect`/`setState`, so Motion committed the non-reduced `initial`/`animate` before
  the flag flipped — reduced-motion users got the fade+rise on EVERY navigation. The spec test only
  asserted the final state (jsdom jumps there), giving false confidence.
- Important: a foundation task said migrate ALL `EASE_OUT` re-declarations to the shared
  `@nightshift-ai/ui` export, but two files kept local copies despite already importing from the
  barrel.

## Preventions

- For any animation that fires on mount (not viewport/interaction-gated), resolve reduced-motion
  synchronously on the first render, not via a post-mount effect — write the test WITHOUT `waitFor`
  so it asserts the first synchronous render is already static.
- When promoting a constant to a shared export, grep the whole workspace for every re-declaration
  and migrate them in the same change.

## Rules written

- post-mount-latch-only-safe-for-viewport-gated-not-onmount (web-engineer)
- reduced-motion-test-must-assert-synchronous-first-render (web-engineer)
